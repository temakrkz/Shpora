# 2.15 Первичный ключ (Primary Key)

---

## Короткий ответ

**Первичный ключ (Primary Key)** — это уникальный идентификатор записи в таблице базы данных. Каждая запись имеет свой собственный первичный ключ, который нельзя повторить или изменить на другой существующий ключ.

---

## Простыми словами

### Аналогия с паспортом

Представьте базу данных как большой офисный архив:

| Объект | Аналогия |
|--------|----------|
| **Запись в таблице** | Файл с документами о клиенте |
| **Первичный ключ** | Номер дела в архиве — уникальный номер, по которому можно найти файл |
| **Дубликаты первичных ключей** | Два файла с одинаковым номером дела — невозможно найти нужный |

### Что такое Primary Key?

**Primary Key (первичный ключ)** — это "паспорт" записи в таблице:
- У каждой записи свой уникальный номер
- Этот номер никогда не повторяется
- По этому номеру можно найти любую запись в таблице

---

## Подробно

### Зачем нужен первичный ключ?

#### 1. Уникальная идентификация записей

**Проблема без Primary Key:**
В таблице заказов:
| order_id | customer_name | total_amount |
|----------|---------------|--------------|
| 123      | Иванов         | 5000         |
| 456      | Петров        | 3000         |

Если удалить `order_id` и добавить только `customer_name`:
| customer_name | total_amount |
|---------------|--------------|
| Иванов         | 5000         |
| Иванов         | 7000         |

**Проблема:** Как понять, какой заказ принадлежит Ивану? Два Ивана с разными заказами.

**Решение:** Первичный ключ однозначно идентифицирует каждую запись:
| order_id (PK) | customer_name | total_amount |
|---------------|---------------|--------------|
| 123           | Иванов         | 5000         |
| 456           | Петров        | 3000         |

#### 2. Связи между таблицами

Первичный ключ используется для создания внешних ключей в других таблицах:

```sql
-- Таблица клиентов с первичным ключом
CREATE TABLE customers (
    customer_id INT PRIMARY KEY,  -- Первичный ключ
    name VARCHAR(100)
);

-- Таблица заказов со ссылкой на клиента
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,              -- Внешний ключ на customers
    total_amount DECIMAL,
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);
```

**Как работает:**
- `customer_id` в таблице заказов ссылается на первичный ключ в таблице клиентов
- Это гарантирует, что заказ связан с существующим клиентом

---

### Требования к первичному ключу

#### 1. Уникальность (Uniqueness)

Каждый первичный ключ должен быть уникальным — не может существовать двух записей с одинаковым ключом.

**Пример:**
```sql
CREATE TABLE users (
    user_id INT PRIMARY KEY,  -- Уникальный ID каждого пользователя
    username VARCHAR(50),
    email VARCHAR(100)
);
```

В этой таблице:
- `user_id = 1` может существовать только один раз
- Нельзя добавить ещё одного пользователя с `user_id = 1`

#### 2. Неизменяемость (Immutability)

Первичный ключ не должен меняться после создания записи.

**Пример:**
```sql
-- Плохая практика: email как первичный ключ
CREATE TABLE users (
    email VARCHAR(100) PRIMARY KEY,  -- Email может измениться!
    name VARCHAR(50),
    phone VARCHAR(20)
);
```

Если пользователь сменил email — нужно обновлять все внешние ключи в других таблицах.

**Правильная практика:**
```sql
-- Правильно: user_id как первичный ключ
CREATE TABLE users (
    user_id INT PRIMARY KEY,  -- Не меняется
    username VARCHAR(50),
    email VARCHAR(100)        -- Может меняться
);
```

#### 3. Отсутствие NULL значений

Первичный ключ не может иметь пустых значений — каждая запись должна иметь идентификатор.

**Пример:**
```sql
CREATE TABLE orders (
    order_id INT PRIMARY KEY,  -- Не может быть NULL
    customer_id INT NOT NULL,
    total_amount DECIMAL
);
```

---

### Типы первичных ключей

#### 1. Суррогатный ключ (Surrogate Key)

**Что это:** Искусственно созданный уникальный идентификатор.

**Пример:**
```sql
CREATE TABLE products (
    product_id INT PRIMARY KEY,  -- Суррогатный ключ: просто число
    sku VARCHAR(50),             -- Бизнес-ключ: артикул товара
    name VARCHAR(100),
    price DECIMAL
);
```

**Преимущества:**
- Простой и быстрый (число)
- Не зависит от бизнес-данных
- Можно создать даже если нет уникального бизнес-идентификатора

#### 2. Естественный ключ (Natural Key)

**Что это:** Существующий в реальном мире уникальный идентификатор.

**Пример:**
```sql
CREATE TABLE employees (
    employee_id INT PRIMARY KEY,      -- Суррогатный ключ
    social_security_number VARCHAR(15),  -- Естественный ключ: ИНН
    name VARCHAR(100)
);
```

**Преимущества:**
- Имеет бизнес-смысл
- Не нужно создавать искусственные идентификаторы

**Недостатки:**
- Может меняться (например, при смене паспорта)
- Занимает больше места (текст вместо числа)

## Пример из интернет-магазина

### Таблица товаров с первичным ключом

```sql
CREATE TABLE products (
    product_id INT PRIMARY KEY,        -- Суррогатный ключ: 1, 2, 3...
    sku VARCHAR(50),                   -- Естественный ключ: SKU товара
    name VARCHAR(100),                 -- Название товара
    category_id INT,                   -- Категория (внешний ключ)
    price DECIMAL,                     -- Цена
    created_at TIMESTAMP               -- Дата создания
);

-- Пример данных
INSERT INTO products VALUES 
(1, 'NB-001', 'Ноутбук ASUS', 1, 50000, '2024-01-15'),
(2, 'PH-002', 'iPhone 13', 2, 70000, '2024-01-16');
```

**Как работает:**
- `product_id = 1` — это уникальный идентификатор ноутбука ASUS
- `sku = 'NB-001'` — это артикул товара (может использоваться в документах)
- По `product_id` можно быстро найти товар в других таблицах

### Таблица заказов с первичным ключом

```sql
CREATE TABLE orders (
    order_id INT PRIMARY KEY,          -- Первичный ключ заказа
    customer_id INT,                   -- Внешний ключ на customers
    total_amount DECIMAL,              -- Сумма заказа
    status VARCHAR(20),                -- Статус: 'pending', 'completed'
    created_at TIMESTAMP               -- Дата создания
);

-- Пример данных
INSERT INTO orders VALUES 
(1001, 456, 75000, 'completed', '2024-01-20'),
(1002, 789, 30000, 'pending', '2024-01-21');
```

**Как работает:**
- `order_id = 1001` — уникальный идентификатор заказа №1001
- По этому ID можно найти все детали заказа в других таблицах (товары, оплата)

## Плюсы и минусы первичных ключей

### ✅ Преимущества использования Primary Key

| Преимущество | Объяснение |
|-------------|------------|
| **Уникальная идентификация** | Каждая запись имеет свой уникальный номер |
| **Связи между таблицами** | Позволяет создавать внешние ключи для отношений между сущностями |
| **Оптимизация запросов** | Индекс на первичный ключ ускоряет поиск записей |
| **Целостность данных** | Гарантирует, что каждая запись может быть найдена и обновлена |

### ❌ Недостатки и ограничения Primary Key

| Недостаток | Объяснение |
|-----------|------------|
| **Неизменяемость** | Первичный ключ не должен меняться после создания записи |
| **Выбор типа ключа важен** | Неправильный выбор может привести к проблемам при изменениях данных |
| **Занимает место в индексе** | Хотя индекс на PK необходим, он занимает ресурсы |

## Что важно запомнить аналитику

1. **Первичный ключ — это уникальный идентификатор записи**  
   Как паспорт для каждой записи в таблице

2. **Лучше использовать суррогатные ключи (числа)**  
   Они не меняются и занимают меньше места, чем естественные ключи (текст)

3. **Первичный ключ используется для внешних ключей**  
   Другие таблицы ссылаются на первичные ключи для создания связей

4. **Аналитик должен правильно выбирать тип Primary Key**  
   Это влияет на производительность и удобство работы с данными

## ❓ Типичные вопросы и ответы

### Вопрос 1: Что такое первичный ключ?
**Ответ:**  
Первичный ключ — это уникальный идентификатор записи в таблице. Каждая запись имеет свой собственный первичный ключ, который не повторяется и не может быть пустым. По первичному ключу можно найти любую запись в таблице.

---

### Вопрос 2: В чём разница между суррогатным и естественным ключом?
**Ответ:**  
Суррогатный ключ — это искусственно созданный идентификатор (например, число 1, 2, 3). Естественный ключ — это существующий в реальном мире уникальный идентификатор (например, email, паспорт). Суррогатные ключи лучше подходят для первичных ключей, так как не меняются и занимают меньше места.

---

### Вопрос 3: Почему нельзя использовать email как первичный ключ?
**Ответ:**  
Потому что email может измениться — пользователь сменил адрес. Если email будет первичным ключом, то при изменении нужно обновлять все внешние ключи в других таблицах, что сложно и рискованно. Лучше использовать суррогатный ключ (число), который не меняется.

---

## 🛠 Практические вопросы для собеседования

### Вопрос 1: Нужно спроектировать таблицу пользователей для интернет-магазина. Какие поля вы бы выбрали для первичного ключа и почему?

**Ответ:**  
Я бы выбрал суррогатный ключ — `user_id INT PRIMARY KEY`. Это число, которое генерируется автоматически при создании записи. Оно не зависит от бизнес-данных (email, телефон), не меняется со временем и занимает меньше места в индексе по сравнению с текстовыми полями.

---

### Вопрос 2: Заказчик просит использовать email как первичный ключ для таблицы клиентов. Как вы ответите?

**Ответ:**  
Я бы объяснил риски: если пользователь сменил email, нужно будет обновлять все внешние ключи в других таблицах (заказы, история покупок). Это сложно и может привести к ошибкам. Лучше использовать суррогатный ключ `customer_id`, а email хранить как обычное поле — его можно менять без влияния на другие таблицы.

---

### Вопрос 3: Как объяснить клиенту важность первичных ключей?

**Ответ:**  
Я бы объяснил на примере архива документов: если у каждого дела будет уникальный номер, то его легко найти и не перепутать с другим. Первичный ключ — это такой "номер дела" для каждой записи в базе данных. Без него невозможно гарантировать целостность данных и связи между таблицами.

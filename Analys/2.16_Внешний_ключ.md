# 2.16 Внешний ключ (Foreign Key)

---

## Короткий ответ

**Внешний ключ (Foreign Key)** — это поле в таблице, которое ссылается на первичный ключ другой таблицы. Он обеспечивает связь между таблицами и гарантирует целостность данных.

---

## Простыми словами

### Аналогия с адресной книгой

Представьте систему заказов интернет-магазина:

| Таблица | Поле | Роль |
|---------|------|------|
| **Клиенты** | `customer_id` (первичный ключ) | Список всех клиентов |
| **Заказы** | `customer_id` (внешний ключ) | Ссылка на клиента, который сделал заказ |

### Что такое Foreign Key?

**Foreign Key (внешний ключ)** — это "ссылка" между таблицами:
- Поле в одной таблице ссылается на первичный ключ другой таблицы
- Гарантирует, что данные связаны корректно
- Предотвращает создание несуществующих связей

---

## Подробно

### Зачем нужен внешний ключ?

#### 1. Связь между таблицами

**Пример:** Клиенты и их заказы

```sql
-- Таблица клиентов (одна запись на клиента)
CREATE TABLE customers (
    customer_id INT PRIMARY KEY,        -- Первичный ключ
    name VARCHAR(100),
    email VARCHAR(100)
);

-- Таблица заказов (много записей на одного клиента)
CREATE TABLE orders (
    order_id INT PRIMARY KEY,           -- Первичный ключ заказа
    customer_id INT,                    -- Внешний ключ на customers
    total_amount DECIMAL,
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)  -- Ссылка!
);
```

**Как работает:**
- `customer_id` в таблице заказов ссылается на первичный ключ в таблице клиентов
- Это гарантирует, что заказ связан с существующим клиентом

#### 2. Обеспечение целостности данных

Внешний ключ предотвращает создание несуществующих связей:

```sql
-- Попытка создать заказ для несуществующего клиента
INSERT INTO orders (order_id, customer_id, total_amount) 
VALUES (1001, 9999, 5000);  -- ОШИБКА! Клиента с ID 9999 не существует

-- Попытка удалить клиента, у которого есть заказы
DELETE FROM customers WHERE customer_id = 123;  
-- ОШИБКА! Нельзя удалить клиента, у которого есть активные заказы
```

**Без внешнего ключа:**
- Можно создать заказ для несуществующего клиента (ID не существует)
- Можно удалить клиента, у которого есть заказы — данные останутся "повисшими"

#### 3. Упрощение запросов

Внешние ключи позволяют легко соединять таблицы:

```sql
-- Получить все заказы конкретного клиента
SELECT o.order_id, o.total_amount, c.name as customer_name
FROM orders o
JOIN customers c ON o.customer_id = c.customer_id
WHERE o.customer_id = 123;
```

### Типы внешних ключей

#### 1. Простой внешний ключ

Ссылается на один первичный ключ:

```sql
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,                    -- Внешний ключ
    total_amount DECIMAL,
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);
```

#### 2. Сложный внешний ключ

Ссылается на несколько первичных ключей:

```sql
-- Таблица заказов (один первичный ключ)
CREATE TABLE orders (
    order_id INT PRIMARY KEY,
    customer_id INT,
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);

-- Промежуточная таблица для связи M:N
CREATE TABLE order_items (
    item_id INT PRIMARY KEY,
    order_id INT,                       -- Внешний ключ на orders
    product_id INT,                     -- Внешний ключ на products
    quantity INT,
    FOREIGN KEY (order_id) REFERENCES orders(order_id),
    FOREIGN KEY (product_id) REFERENCES products(product_id)
);
```

---

### Ограничения внешних ключей

#### 1. CASCADE — Каскадное удаление/обновление

Что делать с заказами, если удалить клиента?

**Вариант 1: Запретить удаление (DEFAULT)**
```sql
FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
ON DELETE RESTRICT;  -- Нельзя удалить клиента с заказами
```

**Вариант 2: Каскадное удаление (CASCADE)**
```sql
FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
ON DELETE CASCADE;   -- При удалении клиента удаляются и все его заказы
```

**Вариант 3: Установка NULL (SET NULL)**
```sql
FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
ON DELETE SET NULL;  -- При удалении клиента customer_id становится NULL
```

#### 2. RESTRICT — Запрет на удаление

По умолчанию большинство СУБД используют `RESTRICT`:
- Нельзя удалить запись, если на неё есть ссылки через внешний ключ
- Предотвращает создание "сиротских" данных

## Пример из интернет-магазина

### Таблица клиентов с первичным ключом

```sql
CREATE TABLE customers (
    customer_id INT PRIMARY KEY,        -- Первичный ключ: 1, 2, 3...
    name VARCHAR(100),                  -- Имя клиента
    email VARCHAR(100)                  -- Email
);

-- Пример данных
INSERT INTO customers VALUES 
(1, 'Иван Иванов', 'ivan@example.com'),
(2, 'Мария Петрова', 'maria@example.com');
```

### Таблица заказов с внешним ключом на клиентов

```sql
CREATE TABLE orders (
    order_id INT PRIMARY KEY,           -- Первичный ключ заказа: 1001, 1002...
    customer_id INT,                    -- Внешний ключ на customers
    total_amount DECIMAL,               -- Сумма заказа
    status VARCHAR(20),                 -- Статус: 'pending', 'completed'
    created_at TIMESTAMP,
    
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)  -- Ссылка!
        ON DELETE RESTRICT              -- Нельзя удалить клиента с заказами
);

-- Пример данных
INSERT INTO orders VALUES 
(1001, 1, 75000, 'completed', '2024-01-20'),  -- Заказ Ивана (customer_id = 1)
(1002, 2, 30000, 'pending', '2024-01-21');   -- Заказ Марии (customer_id = 2)
```

### Таблица товаров с внешним ключом на категории

```sql
CREATE TABLE categories (
    category_id INT PRIMARY KEY,        -- Первичный ключ: 1, 2...
    name VARCHAR(50)                    -- Название: 'Электроника', 'Одежда'
);

-- Пример данных
INSERT INTO categories VALUES 
(1, 'Электроника'),
(2, 'Одежда');

CREATE TABLE products (
    product_id INT PRIMARY KEY,         -- Первичный ключ товара
    name VARCHAR(100),                  -- Название товара
    category_id INT,                    -- Внешний ключ на categories
    price DECIMAL,                      -- Цена
    
    FOREIGN KEY (category_id) REFERENCES categories(category_id)  -- Ссылка!
);

-- Пример данных
INSERT INTO products VALUES 
(1, 'Ноутбук ASUS', 1, 50000),   -- Ноутбук в категории "Электроника"
(2, 'Футболка', 2, 1500);         -- Футболка в категории "Одежда"
```

## Плюсы и минусы внешних ключей

### ✅ Преимущества использования Foreign Key

| Преимущество | Объяснение |
|-------------|------------|
| **Целостность данных** | Гарантирует, что связи между таблицами корректны |
| **Защита от ошибок** | Предотвращает создание несуществующих связей |
| **Упрощение запросов** | Позволяет легко соединять таблицы через JOIN |
| **Автоматическое управление** | Каскадные операции упрощают удаление и обновление данных |

### ❌ Недостатки и ограничения Foreign Key

| Недостаток | Объяснение |
|-----------|------------|
| **Ограничение гибкости** | Нельзя удалить запись, если на неё есть ссылки (без каскада) |
| **Сложность изменений** | Изменение структуры связанной таблицы может повлиять на другие |
| **Производительность** | Проверки внешних ключей замедляют операции вставки и обновления |
| **Не все СУБД поддерживают** | Некоторые NoSQL БД не имеют поддержки внешних ключей |

## Что важно запомнить аналитику

1. **Внешний ключ — это ссылка на первичный ключ другой таблицы**  
   Он обеспечивает связь между таблицами и целостность данных

2. **Внешние ключи предотвращают ошибки**  
   Нельзя создать заказ для несуществующего клиента или удалить клиента с заказами (по умолчанию)

3. **Можно настроить поведение при удалении**  
   CASCADE — удаляет связанные записи, RESTRICT — запрещает удаление

4. **Аналитик должен понимать ограничения внешних ключей**  
   Это помогает правильно проектировать связи между таблицами и предвидеть проблемы

## ❓ Типичные вопросы и ответы

### Вопрос 1: Что такое внешний ключ?
**Ответ:**  
Внешний ключ — это поле в таблице, которое ссылается на первичный ключ другой таблицы. Он обеспечивает связь между таблицами и гарантирует, что данные связаны корректно (например, заказ связан с существующим клиентом).

---

### Вопрос 2: В чём разница между первичным и внешним ключом?
**Ответ:**  
Первичный ключ — это уникальный идентификатор записи в своей таблице. Внешний ключ — это поле, которое ссылается на первичный ключ другой таблицы. Например, `customer_id` в таблице заказов — внешний ключ, который ссылается на `customer_id` (первичный ключ) в таблице клиентов.

---

### Вопрос 3: Что произойдёт, если попытаться удалить клиента, у которого есть заказы?
**Ответ:**  
По умолчанию операция будет запрещена с ошибкой "нарушение внешнего ключа". Это защита от создания "сиротских" данных — заказов без владельца. Чтобы разрешить удаление, нужно настроить каскадное удаление (ON DELETE CASCADE) или явно удалить все заказы перед удалением клиента.

## 🛠 Практические вопросы для собеседования

### Вопрос 1: Нужно спроектировать таблицу заказов с привязкой к клиентам и товарам. Как вы реализуете внешние ключи?

**Ответ:**  
Я бы создал три таблицы: `customers` (клиенты), `products` (товары) и `orders` (заказы). В таблице заказов добавил бы два внешних ключа: `customer_id` на таблицу клиентов и `product_id` на таблицу товаров. Это обеспечит целостность данных — нельзя создать заказ для несуществующего клиента или добавить товар, которого нет в каталоге.

---

### Вопрос 2: Заказчик просит возможность удалять клиентов даже если у них есть активные заказы. Как вы реализуете это?

**Ответ:**  
Я бы предложил два варианта:
1. **Каскадное удаление (ON DELETE CASCADE)** — при удалении клиента автоматически удаляются все его заказы. Это просто, но может привести к потере данных.
2. **Архивирование заказов** — при удалении клиента его заказы перемещаются в таблицу архива `customers_archive`, а из активной таблицы удаляется только запись о клиенте.

Выбор зависит от требований бизнеса: если важно сохранить историю заказов, лучше использовать второй вариант.

---

### Вопрос 3: Как объяснить клиенту необходимость внешних ключей?

**Ответ:**  
Я бы объяснил на примере адресной книги и истории звонков: если у вас есть список контактов и история звонков к ним — вы не хотите иметь записи о звонках к несуществующим контактам. Внешний ключ гарантирует, что каждый звонок связан с реальным человеком из списка контактов. Это предотвращает ошибки и сохраняет целостность данных.

# 2.20 Репликация vs шардирование: в чём разница

---

## Короткий ответ

**Репликация** — это создание нескольких копий данных на разных серверах для повышения доступности и производительности чтения. **Шардирование** — это разделение одной таблицы на части по разным серверам для горизонтального масштабирования.

---

## Простыми словами

### Аналогия с книгами в библиотеке

| Технология | Аналогия |
|-----------|----------|
| **Репликация** | Одна и та же книга есть в трёх разных библиотеках — если одна закроется, можно взять книгу в другой |
| **Шардирование** | Разные книги разделены по разным библиотекам: детективы в первой, фантастика во второй, научная литература в третьей |

### Главное отличие

**Репликация:**
- Данные дублируются на нескольких серверах
- Один и тот же документ есть везде
- Используется для повышения доступности и чтения

**Шардирование:**
- Данные разбиваются на части по разным серверам
- Каждый документ хранится только в одном месте
- Используется для горизонтального масштабирования больших таблиц

---

## Подробно

### Репликация (Replication)

#### Что это?

Репликация — это создание нескольких копий данных на разных серверах:
```
    [Сервер 1] ←→ [Сервер 2] ←→ [Сервер 3]
       ↓           ↓            ↓
   Данные      Копия 1       Копия 2
```

**Как работает:**
- Все серверы содержат полные копии данных
- Изменения на основном сервере синхронизируются с копиями
- Запросы могут распределяться между копиями

#### Типы репликации

**Master-Slave (Основной-Реплика):**
```
    [Master] ←→ [Slave 1] ←→ [Slave 2]
       ↓           ↓            ↓
   Записи      Чтение        Чтение
```
- Один сервер принимает записи (Master)
- Несколько серверов только читают данные (Slaves)

**Master-Master (Основной-Основной):**
```
    [Master 1] ←→ [Master 2]
       ↓           ↓
   Записи      Чтение + Записи
```
- Все серверы могут принимать записи и читать данные

#### Когда применяется?

**Репликация используется когда:**
- Нужно повысить доступность системы (если один сервер упадёт, другие продолжат работать)
- Нужно ускорить чтение данных (запросы распределяются между копиями)
- Нужно географическое распределение (копии в разных регионах)

---

### Шардирование (Sharding)

#### Что это?

Шардирование — это разделение одной большой таблицы на несколько меньших частей по разным серверам:
```
    [Сервер 1]      [Сервер 2]      [Сервер 3]
       ↓               ↓              ↓
   Заказы 2024     Заказы 2025     Заказы 2026
```

**Как работает:**
- Данные делятся по ключу (например, по дате или региону)
- Каждая часть (шард) хранится на отдельном сервере
- Каждый документ хранится только в одном месте

#### Типы шардирования

**Range sharding (диапазонное):**
```sql
-- Заказы 2024 года → Сервер 1
-- Заказы 2025 года → Сервер 2
-- Заказы 2026 года → Сервер 3
SHARD BY RANGE (order_date);
```

**Hash sharding (хэшное):**
```sql
-- Заказы равномерно распределяются между серверами по хэшу customer_id
SHARD BY HASH(customer_id % 3);
```

#### Когда применяется?

**Шардирование используется когда:**
- Таблица слишком большая для одного сервера
- Нужно горизонтальное масштабирование (добавление новых серверов)
- Данные имеют логическую структуру, которую можно использовать для разделения

---

## Сравнение репликации и шардирования

### ✅ Репликация

| Преимущество | Объяснение |
|-------------|------------|
| **Повышение доступности** | Если один сервер упадёт, другие продолжат работать |
| **Улучшение чтения** | Запросы распределяются между копиями |
| **Простота внедрения** | Не требует изменения структуры данных |

### ❌ Репликация

| Недостаток | Объяснение |
|-----------|------------|
| **Не решает проблему больших таблиц** | Все копии содержат полные данные — если таблица слишком большая, все серверы будут перегружены |
| **Сложность записи** | Нужно синхронизировать изменения между копиями |
| **Занимает больше места** | Данные дублируются на нескольких серверах |

### ✅ Шардирование

| Преимущество | Объяснение |
|-------------|------------|
| **Горизонтальное масштабирование** | Можно добавлять новые серверы по мере роста данных |
| **Эффективное использование ресурсов** | Данные распределены между серверами, каждый обрабатывает свою часть |
| **Упрощение удаления старых данных** | Можно удалить целые шарды с устаревшими данными |

### ❌ Шардирование

| Недостаток | Объяснение |
|-----------|------------|
| **Сложность проектирования** | Нужно правильно выбрать ключ шардирования |
| **Проблемы с JOIN** | Соединение данных из разных шардов сложнее и медленнее |
| **Перераспределение данных** | При изменении нагрузки нужно переносить данные между серверами |

## Пример из интернет-магазина

### Сценарий: Хранение заказов за несколько лет

Интернет-магазин обрабатывает 10 миллионов заказов в год. Таблица `orders` содержит данные за последние 5 лет (50 млн записей).

#### Решение с репликацией:
```
    [Сервер 1] ←→ [Сервер 2] ←→ [Сервер 3]
       ↓           ↓            ↓
   Все заказы    Все заказы     Все заказы
```

**Проблема:**
- Каждый сервер хранит все 50 млн записей — это очень много данных
- Даже с репликацией каждый сервер становится "узким местом"

#### Решение с шардированием:
```
    [Сервер 1]      [Сервер 2]      [Сервер 3]
       ↓               ↓              ↓
   Заказы 2024     Заказы 2025     Заказы 2026
```

**Преимущества:**
- Каждый сервер хранит только 10 млн записей — меньше нагрузка
- Можно добавлять новые серверы по мере роста данных
- Упрощается удаление старых данных (удаление целого шарда)

## Что важно запомнить аналитику

1. **Репликация — это дублирование, шардирование — это разделение**  
   Репликация создаёт копии данных, шардирование делит данные на части

2. **Репликация улучшает чтение, шардирование решает проблему больших таблиц**  
   Если нужно ускорить запросы чтения — репликация, если таблица слишком большая — шардирование

3. **Часто используются вместе**  
   Шарды могут быть реплицированы для повышения доступности и производительности чтения

4. **Аналитик должен понимать компромиссы между подходами**  
   Это помогает правильно выбирать стратегию масштабирования для бизнеса

## ❓ Типичные вопросы и ответы

### Вопрос 1: В чём разница между репликацией и шардированием?
**Ответ:**  
Репликация — это создание нескольких копий данных на разных серверах. Все серверы содержат полные данные, что повышает доступность и ускоряет чтение. Шардирование — это разделение одной таблицы на части по разным серверам. Каждый документ хранится только в одном месте, что позволяет горизонтально масштабировать большие таблицы.

---

### Вопрос 2: Когда стоит использовать репликацию?
**Ответ:**  
Репликация подходит когда нужно повысить доступность системы (если один сервер упадёт, другие продолжат работать) или ускорить чтение данных (запросы распределяются между копиями). Но если таблица слишком большая для одного сервера — репликация не поможет.

---

### Вопрос 3: Когда стоит использовать шардирование?
**Ответ:**  
Шардирование подходит когда таблица слишком большая для одного сервера и нужно горизонтальное масштабирование (добавление новых серверов). Также полезно когда данные имеют логическую структуру, которую можно использовать для разделения (по дате, региону и т.д.).

## 🛠 Практические вопросы для собеседования

### Вопрос 1: Интернет-магазин хранит 50 миллионов заказов в таблице на одном сервере. Сервер не справляется с нагрузкой. Как вы предложите решить проблему?

**Ответ:**  
Я бы предложил шардирование таблицы по дате заказа. Разделю данные на части по годам и распределю их между несколькими серверами. Это уменьшит нагрузку на каждый сервер и позволит добавлять новые серверы по мере роста данных. Дополнительно могу предложить репликацию для повышения доступности чтения.

---

### Вопрос 2: Заказчик просит повысить доступность системы, но не хочет усложнять архитектуру. Какую стратегию вы бы предложили?

**Ответ:**  
Я бы предложил репликацию с архитектурой Master-Slave. Один сервер будет принимать записи (Master), а несколько копий будут отвечать на запросы чтения (Slaves). Это повысит доступность — если один сервер упадёт, другие продолжат работать — и ускорит чтение без необходимости изменять структуру данных или добавлять сложную логику шардирования.

---

### Вопрос 3: Как объяснить клиенту разницу между репликацией и шардированием?

**Ответ:**  
Я бы объяснил на примере библиотеки:
- **Репликация** — как одна и та же книга в трёх разных библиотеках. Если одна закроется, можно взять книгу в другой. Это повышает доступность, но занимает больше места.
- **Шардирование** — как разные книги разделены по разным библиотекам: детективы в первой, фантастика во второй. Это позволяет хранить больше книг на нескольких серверах, но сложнее найти книгу из разных библиотек одновременно.

# 2.21 Маппинг данных (data mapping): что такое и зачем нужен

---

## 📌 Короткий ответ

> **Маппинг данных** — это процесс сопоставления полей из одной системы с полями в другой системе при передаче или преобразовании информации. Это "переводчик", который говорит: "поле `user_id` здесь соответствует полю `userId` там".

---

## 💡 Простыми словами

### Аналогия с интернет-магазинам

Представьте, что у вас есть **два разных склада**:
- На складе А товары записаны как: `sku`, `name`, `price`, `category_id`
- На складе Б те же товары называются: `productCode`, `productName`, `cost`, `categoryId`

Когда вы хотите перенести данные со склада А на склад Б, вам нужно **сопоставить** эти поля. Это и есть маппинг данных.

**Без маппинга:**
- Поле `sku` из системы А просто скопируется как `sku` в систему Б
- Но система Б ожидает поле `productCode`, а не `sku`
- Результат: данные не будут правильно отображаться

**С маппингом:**
- Маппинг говорит: "поле `sku` из системы А → это то же самое, что `productCode` в системе Б"
- Поле `name` → `productName`
- Поле `price` → `cost`
- Всё работает корректно

### Пример из интернет-магазина

**Ситуация:** Вы подключаете новую систему логистики (например, СДЭК) к своей системе заказов.

**В вашей системе заказов:**
```json
{
  "order_id": 12345,
  "customer_name": "Иван Петров",
  "total_amount": 5000,
  "status": "new"
}
```

**В системе СДЭК:**
```json
{
  "orderId": 12345,
  "consigneeName": "Иван Петров",
  "sum": 5000,
  "shipmentStatus": "created"
}
```

**Маппинг данных говорит:**
- `order_id` → `orderId` (то же самое)
- `customer_name` → `consigneeName` (в логистике это получатель)
- `total_amount` → `sum` (сумма заказа)
- `status: "new"` → `shipmentStatus: "created"`

Без маппинга система СДЭК не поймёт, что поле `customer_name` — это имя клиента, а не что-то другое.

## 🔍 Подробно

### Что такое маппинг данных?

**Маппинг данных** (data mapping) — это процесс определения соответствия между полями разных систем или структур данных. Это "карта" или "словарь", который объясняет, как данные из одной системы должны быть преобразованы в другую.

### Зачем нужен маппинг?

1. **Разные названия полей**
   - В одной системе поле называется `firstName`, в другой — `first_name`
   - Маппинг говорит: "это одно и то же"

2. **Разная структура данных**
   - В системе А поле `address` — это строка: `"Москва, ул. Ленина 1"`
   - В системе Б поле `address` разбито на части: `street`, `city`, `country`
   - Маппинг объясняет, как разделить одну строку на несколько полей

3. **Разные типы данных**
   - В системе А возраст — число: `25`
   - В системе Б возраст — строка с префиксом: `"25 лет"`
   - Маппинг говорит: "преобразуй число в строку и добавь текст"

4. **Разные форматы**
   - Дата в системе А: `DD.MM.YYYY` → `25.12.2023`
   - Дата в системе Б: `YYYY-MM-DD` → `2023-12-25`
   - Маппинг преобразует формат

### Типы маппинга данных

#### 1. Прямой маппинг (field-to-field)

Самый простой тип — поле к полю:

| Поле в системе А | → | Поле в системе Б |
|------------------|---|------------------|
| `user_id`        | → | `userId`         |
| `email`          | → | `user_email`     |
| `created_at`     | → | `createdAt`      |

#### 2. Трансформационный маппинг (field-to-transformation)

Поле преобразуется в другое значение:

| Поле в системе А | → | Преобразование | → | Поле в системе Б |
|------------------|---|-----------------|---|------------------|
| `status`         | → | если "active" то 1, иначе 0 | → | `is_active`      |
| `phone`          | → | убрать пробелы и скобки | → | `clean_phone`    |

#### 3. Структурный маппинг (structure-to-fields)

Одно поле разбивается на несколько:

| Поле в системе А | → | Разбиение | → | Поля в системе Б |
|------------------|---|-----------|---|------------------|
| `full_address`   | → | разделить по запятой | → | `city`, `street`, `country` |

#### 4. Агрегационный маппинг (fields-to-field)

Несколько полей объединяются в одно:

| Поля из системы А | → | Объединение | → | Поле в системе Б |
|-------------------|---|-------------|---|------------------|
| `first_name`, `last_name` | → | соединить пробелом | → | `full_name`      |

### Где используется маппинг данных?

#### 1. Интеграция систем (API)

Когда вы подключаете новую систему к существующей, нужно маппингировать данные:
- Система заказов ↔ Система доставки
- CRM ↔ Маркетинговая платформа
- Биллинг ↔ Платёжный шлюз

#### 2. ETL процессы (Extract, Transform, Load)

При переносе данных из одной базы в другую:
- Извлечь данные из старой системы
- Преобразовать их по правилам маппинга
- Загрузить в новую систему

#### 3. Миграция баз данных

Когда вы меняете структуру БД или переходите на новую платформу:
- Старая схема → Новая схема
- Поля перемещаются, переименовываются, объединяются

#### 4. Синхронизация данных

При работе с несколькими источниками данных:
- Данные из разных систем должны быть сопоставлены
- Например: данные о клиенте из CRM и данные из системы поддержки

### Пример маппинга в интернет-магазине (подробно)

**Сценарий:** Вы подключаете систему аналитики (например, Яндекс.Метрика или Google Analytics) к своей системе заказов.

**Ваши данные (из системы заказов):**
```json
{
  "order_id": 12345,
  "customer_email": "ivan@example.com",
  "total_amount": 5000,
  "currency": "RUB",
  "items": [
    {
      "product_name": "Смартфон",
      "quantity": 1,
      "price": 3000
    }
  ],
  "order_date": "25.12.2023"
}
```

**Формат, который требует система аналитики:**
```json
{
  "transaction_id": 12345,
  "email": "ivan@example.com",
  "revenue": 5000,
  "currency_code": "RUB",
  "items": [
    {
      "item_name": "Смартфон",
      "quantity": 1,
      "unit_price": 3000
    }
  ],
  "transaction_date": "2023-12-25"
}
```

**Маппинг данных:**

| Поле в системе заказов | → | Преобразование | → | Поле в системе аналитики |
|------------------------|---|----------------|---|--------------------------|
| `order_id`             | → | без изменений  | → | `transaction_id`         |
| `customer_email`       | → | без изменений  | → | `email`                  |
| `total_amount`         | → | без изменений  | → | `revenue`                |
| `currency`             | → | без изменений  | → | `currency_code`          |
| `items[].product_name` | → | без изменений  | → | `items[].item_name`      |
| `order_date`           | → | формат DD.MM.YYYY → YYYY-MM-DD | → | `transaction_date`       |

**Без маппинга:** Система аналитики не поймёт, что поле `customer_email` — это email клиента. Она может считать его просто "email" без контекста.

## ✅ Плюсы и минусы маппинга данных

### ✅ Преимущества

| Преимущество | Объяснение |
|--------------|------------|
| **Универсальность** | Позволяет работать с системами, которые используют разные названия полей и структуры данных |
| **Гибкость** | Можно легко менять интеграции без изменения кода — достаточно обновить маппинг |
| **Безопасность данных** | Данные не теряются при передаче между системами — каждое поле правильно сопоставлено |
| **Упрощение разработки** | Разработчикам не нужно писать сложную логику преобразования — всё описано в конфигурации |

### ❌ Недостатки и риски

| Недостаток | Объяснение |
|------------|------------|
| **Сложность при масштабировании** | Чем больше систем интегрируется, тем сложнее поддерживать маппинг-конфигурацию |
| **Риск ошибок** | Если маппинг настроен неправильно, данные будут передаваться неверно, но ошибка проявится только позже |
| **Зависимость от документации** | Без понятной документации сложно понять, как именно сопоставлены поля разных систем |

---

## 📌 Что важно запомнить аналитику

1. **Маппинг данных — это "словарь" между системами**, который объясняет, как поля из одной системы соответствуют полям в другой
2. **Без маппинга интеграции не работают** — разные системы используют разные названия и структуры полей
3. **Аналитик должен участвовать в создании маппинга**, чтобы убедиться, что данные передаются корректно и бизнес-логика сохраняется
4. **Маппинг может быть простым (поле к полю) или сложным (с преобразованиями)**, но всегда требует документирования

## ❓ Типичные вопросы и ответы

### Вопрос 1: Что такое маппинг данных для аналитика?
**Ответ:** Маппинг данных — это процесс сопоставления полей из одной системы с полями в другой. Например, поле `user_id` в вашей системе может соответствовать полю `userId` в системе доставки. Аналитик должен понимать этот процесс, чтобы правильно проектировать интеграции между системами и убедиться, что данные передаются корректно.

### Вопрос 2: Почему маппинг данных важен при разработке API?
**Ответ:** Маппинг данных важен потому, что разные системы используют разные названия полей и структуры данных. Без правильного маппинга данные могут быть неправильно интерпретированы или потеряны. Например, поле `status` в одной системе может иметь значения "active", "inactive", а в другой — 1 и 0. Маппинг объясняет это соответствие.

### Вопрос 3: Какие ошибки чаще всего возникают при маппинге данных?
**Ответ:** Основные ошибки:
- **Неправильное сопоставление полей** — поле `first_name` ошибочно сопоставлено с `last_name`
- **Игнорирование преобразований** — дата в формате DD.MM.YYYY не конвертируется в YYYY-MM-DD
- **Потеря данных при агрегации** — несколько полей объединяются, но одно из них случайно исключается

## 🛠 Практические вопросы для собеседования

### Вопрос 1: Вам нужно интегрировать систему заказов с системой доставки. Поля имеют разные названия и структуру. Как вы подойдёте к задаче маппинга данных?

**Ответ:**  
Я бы начал с анализа обеих систем:
1. **Изучил документацию** обеих систем — какие поля они используют, как называются, в каком формате
2. **Создал таблицу соответствия** — сопоставил каждое поле из системы заказов с полем в системе доставки
3. **Определил преобразования** — если нужно менять формат данных (например, дату или валюту), задокументировал правила
4. **Проверил маппинг тестовыми данными** — отправил несколько заказов и убедился, что система доставки их правильно обработала

---

### Вопрос 2: Вы видите, что после интеграции с новой CRM данные о клиентах отображаются неверно. Ваши действия?

**Ответ:**  
Я бы проверил следующие моменты:
1. **Сначала посмотрел маппинг-конфигурацию** — возможно, поле `customer_name` ошибочно сопоставлено не с тем полем в CRM
2. **Проверил формат данных** — например, если дата была отправлена в формате DD.MM.YYYY, а система ожидала YYYY-MM-DD
3. **Убедился, что преобразования работают корректно** — особенно для сложных полей (например, адреса, которые нужно разбить на части)

---

### Вопрос 3: Как вы объясните маппинг данных бизнесу?

**Ответ:**  
Я бы использовал аналогию с переводом документов:
"Представьте, что ваша система заказов говорит на одном языке, а система доставки — на другом. Маппинг данных — это как словарь или переводчик, который помогает им понять друг друга. Например, в вашей системе поле называется `customer_name`, а в системе доставки — `consigneeName`. Это одно и то же поле, просто названо по-разному. Маппинг объясняет эту связь."

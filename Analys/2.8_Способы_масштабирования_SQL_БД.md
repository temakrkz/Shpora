# 2.8 Способы масштабирования SQL БД: вертикальное и горизонтальное

---

## Короткий ответ

**Масштабирование SQL БД** — это увеличение производительности базы данных путём добавления ресурсов (вертикальное) или распределения нагрузки на несколько серверов (горизонтальное).

---

## Простыми словами

### Аналогия с офисом

Представьте бухгалтерию интернет-магазина:

| Способ | Аналогия |
|--------|----------|
| **Вертикальное** | Купить более мощный компьютер и больше памяти для одного бухгалтера |
| **Горизонтальное** | Нанять двух новых бухгалтеров и разделить работу между ними |

---

## Подробно

### Вертикальное масштабирование (Scale Up)

**Что это:** Увеличение мощности одного сервера БД.

**Как реализуется:**
- Добавление процессора (CPU)
- Увеличение оперативной памяти (RAM)
- Установка более быстрых дисков (SSD вместо HDD)

**Когда применяется:**
- Когда нагрузка растёт постепенно и предсказуемо
- Когда нужно быстро увеличить мощность без изменения архитектуры
- Для небольших и средних систем

### Горизонтальное масштабирование (Scale Out)

**Что это:** Добавление новых серверов БД для распределения нагрузки.

**Как реализуется:**
- Разделение данных между несколькими серверами (шардирование)
- Репликация данных на несколько копий
- Распределение запросов между серверами

**Когда применяется:**
- Когда одного сервера недостаточно для обработки нагрузки
- Когда нужно обеспечить высокую доступность системы
- Для крупных систем с большой нагрузкой

### Сравнение подходов

| Критерий | Вертикальное (Scale Up) | Горизонтальное (Scale Out) |
|----------|------------------------|----------------------------|
| **Сложность** | Простое: замена оборудования | Сложное: изменение архитектуры |
| **Стоимость** | Дорого: покупка мощного сервера | Дешевле: несколько обычных серверов |
| **Ограничения** | Есть предел мощности одного сервера | Практически без ограничений |
| **Время внедрения** | Быстро: замена железа | Долго: перенос данных, настройка |
| **Простой** | Простой: перезагрузка или смена оборудования | Сложный: нужно синхронизировать все серверы |

---

## Пример из интернет-магазина

### Сценарий роста продаж

Интернет-магазин растёт и количество заказов увеличивается в 10 раз за год.

**Вертикальное масштабирование:**
- Покупается более мощный сервер с процессором 32 ядра вместо 8 ядер
- Устанавливается 512 ГБ оперативной памяти вместо 64 ГБ
- **Результат:** Один сервер справляется с нагрузкой, но дорого

**Горизонтальное масштабирование:**
- Данные о заказах делятся между тремя серверами (по 3 месяца истории на каждом)
- Запросы распределяются автоматически в зависимости от даты заказа
- Если один сервер не справляется — добавляется четвёртый
- **Результат:** Система растёт вместе с бизнесом, но сложнее в настройке

## Плюсы и минусы масштабирования SQL БД

### ✅ Вертикальное масштабирование (Scale Up)

| Преимущество | Объяснение |
|-------------|------------|
| **Простота внедрения** | Не нужно менять архитектуру системы |
| **Быстрый результат** | Замена оборудования занимает несколько часов |
| **Нет сложной синхронизации** | Один сервер — одна точка управления |

### ❌ Вертикальное масштабирование (Scale Up)

| Недостаток | Объяснение |
|-----------|------------|
| **Ограниченная мощность** | Есть предел, когда один сервер не справится |
| **Высокая стоимость** | Мощные серверы стоят дорого |
| **Простоить при отказе** | Если сервер упадёт, нужно ждать поставки нового оборудования |

### ✅ Горизонтальное масштабирование (Scale Out)

| Преимущество | Объяснение |
|-------------|------------|
| **Безграничный рост** | Можно добавлять сколько угодно серверов |
| **Высокая доступность** | Если один сервер упадёт, другие продолжат работать |
| **Экономичнее в долгосрочной перспективе** | Несколько обычных серверов дешевле одного мощного |

### ❌ Горизонтальное масштабирование (Scale Out)

| Недостаток | Объяснение |
|-----------|------------|
| **Сложная архитектура** | Нужно правильно разделить данные между серверами |
| **Долгое внедрение** | Перенос данных и настройка занимают недели или месяцы |
| **Проблемы с согласованностью** | Данные на разных серверах должны быть синхронизированы |

---

## Что важно запомнить аналитику

1. **Выбор способа масштабирования зависит от бизнес-требований**  
   Если важна скорость внедрения — вертикальное, если нужна масштабируемость — горизонтальное

2. **Часто используется комбинация подходов**  
   Сначала увеличивается мощность одного сервера, а при необходимости добавляются новые серверы

3. **Горизонтальное масштабирование требует тщательного проектирования**  
   Нужно заранее продумать, как будут распределяться данные между серверами

4. **Для аналитика важно понимать ограничения каждого подхода**  
   Это поможет правильно оценить требования к инфраструктуре при проектировании системы

## ❓ Типичные вопросы и ответы

### Вопрос 1: В чём разница между вертикальным и горизонтальным масштабированием?
**Ответ:**  
Вертикальное — это увеличение мощности одного сервера (больше процессоров, памяти). Горизонтальное — добавление новых серверов для распределения нагрузки.

---

### Вопрос 2: Когда лучше использовать вертикальное масштабирование?
**Ответ:**  
Когда нужно быстро увеличить мощность без изменения архитектуры системы, и нагрузка предсказуемо растёт в пределах возможностей одного сервера.

---

### Вопрос 3: Какие проблемы возникают при горизонтальном масштабировании?
**Ответ:**  
Основные сложности — распределение данных между серверами, обеспечение согласованности данных и высокая стоимость внедрения из-за необходимости переноса данных.

---

## 🛠 Практические вопросы для собеседования

### Вопрос 1: Интернет-магазин обрабатывает 100 000 заказов в день. Один сервер справляется с 50 000 заказов. Что вы предложите?

**Ответ:**  
Я бы предложил горизонтальное масштабирование — добавить второй сервер и разделить нагрузку по датам (например, чётные дни на одном сервере, нечётные на другом). Это позволит обрабатывать больше заказов без покупки сверхмощного оборудования.

---

### Вопрос 2: Базовая система работает медленно. Заказчик просит увеличить производительность "прямо сейчас". Что вы бы сделали?

**Ответ:**  
Я бы предложил вертикальное масштабирование — добавить оперативной памяти и процессорных ядер на текущем сервере. Это самый быстрый способ улучшить производительность без изменения архитектуры системы.

---

### Вопрос 3: Как определить, какой способ масштабирования подходит для вашей системы?

**Ответ:**  
Я бы проанализировал несколько факторов:
- **Объём данных** — если данные больше, чем может вместить один сервер, нужно горизонтальное масштабирование
- **Бюджет и сроки** — вертикальное дешевле и быстрее в краткосрочной перспективе
- **Требования к доступности** — горизонтальное обеспечивает лучшую отказоустойчивость

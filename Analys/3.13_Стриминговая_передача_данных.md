# 3.13 Стриминговая передача данных

> **Короткий ответ**  
> Стриминг — это передача больших объёмов данных частями (потоками) по мере их готовности, а не ожидание полной загрузки всех данных перед отправкой.

> **Простыми словами**  
> Представьте видео на YouTube: вы начинаете смотреть его сразу, даже если файл ещё полностью не скачался. Стриминг — это как онлайн-трансляция: данные приходят и передаются по мере их поступления, а не ждут полной загрузки.

> **Подробно**  
> **Стриминговая передача данных** — это способ передачи больших объёмов информации частями (chunks), где клиент начинает потреблять данные сразу после получения первой части, не дожидаясь завершения всей передачи.

> **Как это работает:**
> 1. Сервер отправляет данные небольшими порциями (например, по 10-100 KB)
> 2. Клиент отображает/обрабатывает полученные данные
> 3. Сервер продолжает отправлять следующие порции
> 4. Передача продолжается до конца данных

> **Техническая реализация:**
> - HTTP Chunked Transfer Encoding — заголовок `Transfer-Encoding: chunked`
> - Server-Sent Events (SSE) — сервер иницирует поток событий
> - WebSocket — двусторонний постоянный канал связи

## Пример из интернет-магазина

**Сценарий:** Пользователь просит посмотреть список товаров с 10 000 позициями.

### Без стриминга (обычный подход):
```
GET /products?page=1&limit=10000
# Сервер собирает все 10 000 товаров → формирует JSON → отправляет
# Клиент ждёт 5 секунд → получает весь ответ → начинает отображать
```

**Проблема:** Пользователь видит «Загрузка...» 5 секунд, прежде чем увидеть хоть что-то.

### Со стримингом:
```
GET /products?page=1&limit=10000&stream=true
# Сервер отправляет первые 10 товаров (200 байт)
# Клиент сразу показывает карточки первых 10 товаров
# Через 50 мс приходят следующие 10 товаров → обновляется страница
# ... и так далее до конца списка
```

**Преимущество:** Пользователь видит результат почти мгновенно, а остальное подгружается в фоне.

## Плюсы/минусы

| Плюсы | Минусы |
|-------|--------|
| **Мгновенный отклик** — пользователь начинает видеть данные сразу | **Сложность реализации** — нужно разделять большие данные на chunks |
| **Экономия памяти клиента** — не нужно загружать всё сразу | **Проблемы с кэшированием** — сложно кэшировать потоковые ответы |
| **Лучше UX для больших данных** — прогрессивная загрузка | **Не подходит для маленьких ответов** — накладные расходы больше пользы |
| **Меньше риск таймаута** — данные передаются постепенно | **Сложность отладки** — трудно воспроизвести ошибки |

## Что важно запомнить аналитику

1. **Стриминг ≠ Асинхронность**  
   Стриминг — это про то, как передаются данные (частями). Асинхронность — про то, когда происходит обработка (не ждём ответа).

2. **HTTP Chunked Transfer Encoding**  
   Позволяет отправлять данные без указания размера тела запроса заранее. Сервер пишет `Transfer-Encoding: chunked` в заголовке.

3. **Server-Sent Events (SSE)**  
   Спецификация для однонаправленного потока событий от сервера к клиенту. Идеально для уведомлений, чатов, live-обновлений.

4. **WebSocket**  
   Двусторонний постоянный канал — подходит и для push-уведомлений, и для интерактивных чатов.

## Типичные вопросы и ответы

**Q: В чём разница между стримингом и асинхронностью?**  
A: Стриминг — это про передачу данных частями (как доставляется). Асинхронность — про нежидание ответа (когда происходит обработка).

**Q: Когда использовать HTTP Chunked Transfer Encoding?**  
A: Для больших ответов, когда размер заранее неизвестен или нужно начать передачу сразу.

**Q: Что такое Server-Sent Events и когда их использовать?**  
A: SSE — это однонаправленный поток событий от сервера к клиенту. Идеально для уведомлений о статусе заказа, ценниках в реальном времени.

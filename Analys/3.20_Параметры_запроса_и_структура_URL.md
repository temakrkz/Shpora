# 3.20 Параметры запроса и структура URL

> **Короткий ответ**  
> Структура URL в RESTful API состоит из базового пути, идентификаторов ресурсов и параметров (path params, query params). Правильная структура делает API понятным и предсказуемым.

> **Простыми словами**  
> Представьте адрес магазина:
> - `/products` — каталог товаров
> - `/products/123` — конкретный товар с ID 123
> - `/products?category=electronics&sort=price_asc` — товары из категории электроники, отсортированные по цене

> **Подробно**  
> **Параметры запроса** и **структура URL** — это способ указания того, какие данные нужны серверу. В RESTful API используются три типа параметров: path params, query params и fragment (не используется в API).

## Типы параметров

### 1. Path Parameters (параметры пути)

**Что это:** Части URL, которые идентифицируют конкретный ресурс.

**Пример из интернет-магазина:**
```
GET /products/123          # Товар с ID 123
GET /users/me/orders       # Заказы текущего пользователя (me — special path param)
GET /categories/electronics#phones  # Телефоны в категории электроники
```

**Правила:**
- Path params идентифицируют конкретный ресурс
- Обычно передаются через `{param}` в OpenAPI
- **Не должны содержать спецсимволы** (пробелы, &, ?)

### 2. Query Parameters (параметры запроса)

**Что это:** Дополнительные параметры для фильтрации, сортировки, пагинации.

**Пример из интернет-магазина:**
```
GET /products?page=1&limit=20          # Пагинация: страница 1, 20 товаров
GET /products?category=electronics      # Фильтр по категории
GET /products?min_price=1000&max_price=5000  # Диапазон цен
GET /products?sort=price_asc            # Сортировка по цене (возрастание)
GET /products?search=laptop             # Поиск по названию
```

**Правила:**
- Query params используются для фильтрации, сортировки, пагинации
- **Не должны идентифицировать ресурс** (это задача path params)
- Могут быть дублирующимися (не должно быть `/products?category=electronics&category=phones`)

### 3. Fragment Parameters (фрагменты) — не используются в API

**Что это:** Часть URL после символа `#`, которая видна только клиенту (браузеру).

**Пример:**
```
https://example.com/products/123?category=electronics#reviews
                                    ↑           ↑
                                query param   fragment (виден только в браузере)
```

**Правила:**
- **Не передаются на сервер!** Браузер отрезает всё после `#` перед отправкой запроса
- Используются для навигации внутри страницы (якорные ссылки)

## Пример из интернет-магазина

### Полный URL с параметрами:
```
GET https://shop.example.com/products/123?category=electronics&sort=price_asc&page=1&limit=20
                                    ↑           ↑              ↑            ↑
                                path param   query params (filter, sort, pagination)
```

**Разбор:**
- `/products/123` — конкретный товар с ID 123
- `category=electronics` — фильтр по категории
- `sort=price_asc` — сортировка по цене (возрастание)
- `page=1&limit=20` — пагинация: первая страница, 20 товаров

## Плюсы/минусы разных типов параметров

| Тип | Плюсы | Минусы |
|-----|-------|--------|
| **Path params** | Чётко идентифицируют ресурс | Не подходят для фильтрации/сортировки |
| **Query params** | Гибкие, легко добавлять новые фильтры | Могут быть слишком длинными (URL-лимиты) |
| **Fragment** | Удобно для навигации в браузере | Не передаются на сервер (не используются в API) |

## Что важно запомнить аналитику

1. **Path params идентифицируют ресурс, query params фильтруют/сортируют**  
   `/products/123` — конкретный товар<br>`/products?category=electronics` — фильтр по категории

2. **URL-лимиты:**
   - Большинство браузеров поддерживают URL до 2048 символов
   - Некоторые прокси/серверы имеют лимиты (512, 1024 символа)
   - Длинные query params могут быть обрезаны

3. **URL-парсинг:**
   - Браузер отрезает всё после `#` перед отправкой запроса
   - Сервер видит только path и query params

4. **OpenAPI спецификация:**
   ```yaml
   paths:
     /products/{id}:
       get:
         parameters:
           - name: id
             in: path  # Path param
             required: true
           - name: category
             in: query  # Query param
             schema:
               type: string
   ```

## Типичные вопросы и ответы

**Q: В чём разница между path params и query params?**  
A: Path params идентифицируют конкретный ресурс (`/products/123`). Query params используются для фильтрации, сортировки, пагинации (`?category=electronics&sort=price_asc`).

**Q: Почему фрагменты (#) не передаются на сервер?**  
A: Браузер отрезает всё после символа `#` перед отправкой HTTP-запроса. Фрагменты видны только клиенту для навигации внутри страницы.

**Q: Какие риски возникают при использовании длинных URL с query params?**  
A: URL-лимиты браузеров (2048 символов), прокси/серверов (512, 1024 символа). Длинные URL могут быть обрезаны или отклонены.

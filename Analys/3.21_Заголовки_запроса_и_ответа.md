# 3.21 Заголовки (headers) запроса и ответа

> **Короткий ответ**  
> HTTP-заголовки — это метаданные, которые сопровождают каждый запрос и ответ: авторизация (`Authorization`), тип контента (`Content-Type`), кодировка (`Accept-Encoding`) и т.д.

> **Простыми словами**  
> Представьте письмо между интернет-магазином и клиентом:
> - **Заголовок письма:** «От кого», «Кому», «Тема» (это HTTP headers)
> - **Тело письма:** само сообщение с данными (это body запроса/ответа)

> **Подробно**  
> **HTTP Headers** — это ключ-значение пары, которые передаются вместе с каждым HTTP-запросом и ответом. Они содержат метаданные о запросе: авторизация, тип контента, кодировка, лимиты и т.д.

## Основные заголовки запроса (Request Headers)

### 1. Authorization
**Что это:** Авторизационные данные для доступа к защищённым ресурсам.

**Примеры из интернет-магазина:**
```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...  # JWT токен
Authorization: Basic YWRtaW46cGFzc3dvcmQ=                       # Basic Auth (base64)
X-API-Key: sk_live_51HxYz...                                    # API Key для сервисов
```

### 2. Content-Type
**Что это:** Формат данных в теле запроса (body).

**Примеры из интернет-магазина:**
```
Content-Type: application/json           # JSON данные
Content-Type: application/xml            # XML данные
Content-Type: multipart/form-data         # Загрузка файлов
Content-Type: text/plain                 # Текстовые данные
```

### 3. Accept
**Что это:** Формат данных, который клиент хочет получить в ответе.

**Примеры из интернет-магазина:**
```
Accept: application/json                # Хочу JSON
Accept: application/xml                 # Хочу XML
Accept: text/html                       # Хочу HTML (браузер)
Accept: */*                             # Любый формат
```

### 4. Accept-Encoding
**Что это:** Форматы сжатия, которые клиент поддерживает.

**Примеры из интернет-магазина:**
```
Accept-Encoding: gzip, deflate          # Поддерживаю gzip и deflate
Accept-Encoding: br                     # Поддерживаю Brotli (современный браузер)
```

### 5. X-Request-ID / Correlation ID
**Что это:** Уникальный идентификатор запроса для отладки.

**Пример из интернет-магазина:**
```
X-Request-ID: abc123xyz789              # Уникальный ID для отслеживания ошибки
# Если что-то пойдёт не так, можно найти этот запрос в логах сервера
```

### 6. User-Agent
**Что это:** Информация о клиенте (браузер, ОС, приложение).

**Примеры из интернет-магазина:**
```
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/91.0...
User-Agent: Mobile Safari/537.36        # Мобильный браузер
User-Agent: MyApp/2.1.0 (iOS 14.0)       # Мобильное приложение
```

## Основные заголовки ответа (Response Headers)

### 1. Content-Type
**Что это:** Формат данных в теле ответа.

**Примеры из интернет-магазина:**
```
Content-Type: application/json           # JSON ответ
Content-Type: text/html                  # HTML страница
Content-Type: image/png                  # Картинка
```

### 2. Cache-Control
**Что это:** Инструкции для кэширования ответа.

**Примеры из интернет-магазина:**
```
Cache-Control: public, max-age=3600      # Можно кэшировать 1 час (публичный контент)
Cache-Control: no-cache                  # Нельзя кэшировать (каждый запрос уникален)
Cache-Control: private, max-age=60       # Кэшировать только на клиенте 1 минута
```

### 3. X-Total-Count / X-Pagination
**Что это:** Метаданные о пагинации.

**Примеры из интернет-магазина:**
```
X-Total-Count: 150                       # Всего товаров в каталоге: 150
X-Page: 1                                # Текущая страница: 1
X-Limit: 20                              # Товаров на странице: 20
X-Total-Pages: 8                         # Всего страниц: 8
```

### 4. X-RateLimit-Remaining / Retry-After
**Что это:** Информация о лимитах запросов (rate limiting).

**Примеры из интернет-магазина:**
```
X-RateLimit-Limit: 100                   # Лимит запросов в минуту: 100
X-RateLimit-Remaining: 95                # Осталось запросов: 95
Retry-After: 60                          # Повторите запрос через 60 секунд (при превышении лимита)
```

### 5. Location
**Что это:** URL созданного ресурса (после успешного создания).

**Пример из интернет-магазина:**
```
POST /orders { "items": [...] }
Response: 
{ "order_id": "ORD-001" }
Location: https://shop.example.com/orders/ORD-001  # URL созданного заказа
```

### 6. ETag / If-Match / If-None-Match
**Что это:** Для оптимистичной блокировки и conditional requests.

**Пример из интернет-магазина:**
```
# Сервер отправляет ETag с ресурсом
GET /products/123
Response: 
{ "name": "iPhone 12" }
ETag: "abc123xyz789"

# Клиент хочет обновить товар — проверяет, что данные не изменились
PUT /products/123 { "name": "iPhone 12 Pro" }
If-Match: "abc123xyz789"

# Если ETag совпадает → обновление прошло успешно
# Если ETag не совпадает → ресурс был изменён другим пользователем (конфликт)
```

## Пример из интернет-магазина

### Запрос с заголовками:
```http
POST https://shop.example.com/orders
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...  # Токен пользователя
Content-Type: application/json                                  # JSON в теле запроса
Accept: application/json                                        # Хочу JSON ответ
X-Request-ID: abc123xyz789                                      # ID для отладки

{
  "items": [
    { "product_id": 123, "quantity": 2 }
  ]
}
```

### Ответ с заголовками:
```http
HTTP/1.1 201 Created
Content-Type: application/json                                  # JSON ответ
Cache-Control: no-cache                                         # Нельзя кэшировать (уникальный заказ)
X-Request-ID: abc123xyz789                                      # Тот же ID для отладки
Location: https://shop.example.com/orders/ORD-001               # URL созданного заказа
X-RateLimit-Limit: 100                                          # Лимит запросов в минуту
X-RateLimit-Remaining: 99                                       # Осталось запросов

{
  "order_id": "ORD-001",
  "status": "created",
  "total_amount": 5000
}
```

## Плюсы/минусы использования заголовков

| Плюсы | Минусы |
|-------|--------|
| **Гибкость** — можно передавать много метаданных без изменения структуры данных | **Сложность отладки** — нужно уметь читать и анализировать заголовки |
| **Не влияют на структуру тела запроса/ответа** | **Лимиты длины заголовков** (обычно 8-16 KB) |
| **Кэширование** — заголовки управляют кэшированием ответов | **Безопасность** — некоторые заголовки могут быть подделаны (X-Custom-Header) |

## Что важно запомнить аналитику

1. **Authorization ≠ Content-Type**  
   - Authorization: авторизация (токен, пароль)
   - Content-Type: формат данных в теле запроса/ответа

2. **Request Headers vs Response Headers:**
   - Request Headers: что клиент хочет отправить/получить
   - Response Headers: что сервер возвращает о самом ответе

3. **Кэширование через заголовки:**
   - `Cache-Control: public` — можно кэшировать на прокси/CDN
   - `Cache-Control: private` — кэшировать только на клиенте (персональные данные)
   - `Cache-Control: no-cache` — каждый запрос должен быть уникальным

4. **Rate Limiting через заголовки:**
   - `X-RateLimit-Limit`: общий лимит
   - `X-RateLimit-Remaining`: сколько осталось
   - `Retry-After`: когда можно повторить запрос после превышения лимита

## Типичные вопросы и ответы

**Q: В чём разница между Content-Type в запросе и ответе?**  
A: В запросе — это формат данных, которые клиент отправляет (JSON, XML). В ответе — это формат данных, которые сервер возвращает.

**Q: Зачем нужен заголовок X-Request-ID?**  
A: Для отладки. Если что-то пойдёт не так, можно найти этот запрос в логах сервера по уникальному ID.

**Q: Что такое ETag и как он используется для оптимистичной блокировки?**  
A: ETag — это хэш версии ресурса. При обновлении клиент отправляет If-Match с предыдущим ETag. Если ресурс был изменён другим пользователем, сервер вернёт ошибку 412 Precondition Failed.

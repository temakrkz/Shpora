# 3.22 Коды ответов HTTP: 200 vs 201, 401 vs 403

> **Короткий ответ**  
> HTTP-коды ответов — это стандартные коды, которые сервер возвращает клиенту для указания результата запроса: 2xx (успех), 4xx (ошибка клиента), 5xx (ошибка сервера).

> **Простыми словами**  
> Представьте диалог между интернет-магазином и клиентом:
> - **200 OK:** «Запрос принят, всё хорошо»
> - **201 Created:** «Ресурс создан успешно»
> - **401 Unauthorized:** «Нет прав доступа (нужен токен/пароль)»
> - **403 Forbidden:** «Есть доступ, но нет прав на это действие»

> **Подробно**  
> **HTTP Status Codes** — это трёхзначные коды, которые сервер возвращает клиенту для указания результата HTTP-запроса. Коды делятся на 5 категорий:
> - **1xx:** Информационные (процесс идёт)
> - **2xx:** Успех (запрос обработан корректно)
> - **3xx:** Перенаправление (нужно сделать ещё один запрос)
> - **4xx:** Ошибка клиента (некорректный запрос)
> - **5xx:** Ошибка сервера (проблема на стороне сервера)

## 200 vs 201 — когда что использовать

### HTTP 200 OK

**Когда использовать:**
- Получение данных (`GET`)
- Обновление данных (`PATCH`, `PUT` с частичным обновлением)
- Удаление данных (`DELETE`)
- Любые операции, которые не создают новый ресурс

**Пример из интернет-магазина:**
```http
# GET — получить данные
GET /products/123
Response: 200 OK
{ "id": 123, "name": "iPhone 12", "price": 7999 }

# PATCH — частичное обновление (не создаёт новый ресурс)
PATCH /orders/456 { "status": "shipped" }
Response: 200 OK
{ "order_id": 456, "status": "shipped" }

# DELETE — удалить ресурс
DELETE /products/123
Response: 200 OK (или 204 No Content)
```

### HTTP 201 Created

**Когда использовать:**
- Создание нового ресурса (`POST`)
- Когда сервер создаёт уникальный ID для созданного ресурса

**Пример из интернет-магазина:**
```http
# POST — создать новый заказ
POST /orders { "items": [...] }
Response: 201 Created
Location: https://shop.example.com/orders/ORD-001
{
  "order_id": "ORD-001",
  "status": "created",
  "total_amount": 5000
}

# POST — создать новый товар (сервер сам присвоил ID)
POST /products { "name": "iPhone 12" }
Response: 201 Created
Location: https://shop.example.com/products/123
{ "id": 123, "name": "iPhone 12", "price": 7999 }
```

**Ключевое отличие:**
- **200 OK:** данные уже существовали или операция не создавала ресурс
- **201 Created:** сервер создал новый уникальный ресурс и вернул его Location

## 401 vs 403 — авторизация vs права доступа

### HTTP 401 Unauthorized (Нет авторизации)

**Когда использовать:**
- Пользователь не вошёл в систему (нет токена/пароля)
- Токен истёк или невалиден
- Нужно перелогиниться

**Пример из интернет-магазина:**
```http
# Запрос без токена
GET /user/profile
Response: 401 Unauthorized
# Клиенту нужно войти в систему и получить токен

# Токен истёк
POST /orders { "items": [...] }
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...  # истёкший токен
Response: 401 Unauthorized
# Клиенту нужно получить новый токен (через refresh token или перелогин)

# Невалидный токен
GET /products
Authorization: Bearer invalid_token_xyz789
Response: 401 Unauthorized
```

### HTTP 403 Forbidden (Нет прав доступа)

**Когда использовать:**
- Пользователь вошёл в систему, но у него нет прав на это действие
- Ресурс приватный и пользователь не имеет доступа
- Административные действия требуют elevated privileges

**Пример из интернет-магазина:**
```http
# Попытка удалить чужой заказ (у пользователя есть токен, но нет права)
DELETE /orders/456  # Заказ принадлежит другому пользователю
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...  # валидный токен
Response: 403 Forbidden
# У пользователя нет права удалять чужие заказы

# Попытка изменить настройки магазина (нужны админские права)
PUT /shop/settings { "tax_rate": 20 }
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...  # токен обычного пользователя
Response: 403 Forbidden
# У пользователя нет роли admin

# Попытка получить приватные данные другого пользователя
GET /users/789/orders
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...  # токен текущего пользователя
Response: 403 Forbidden
# Можно смотреть только свои заказы (GET /my-orders)
```

## Сравнение кодов ответов

| Код | Категория | Когда использовать | Пример из интернет-магазина |
|-----|-----------|-------------------|----------------------------|
| **200 OK** | Успех | Получение/обновление/удаление данных | GET /products, PATCH /orders/{id} |
| **201 Created** | Успех | Создание нового ресурса | POST /orders (создание заказа) |
| **204 No Content** | Успех | Операция выполнена, нет ответа в body | DELETE /products/{id} |
| **400 Bad Request** | Ошибка клиента | Неверные данные запроса | POST /orders { "items": [] } (пустой массив) |
| **401 Unauthorized** | Ошибка авторизации | Нет токена/пароля, токен истёк | GET /profile без Authorization header |
| **403 Forbidden** | Ошибка прав доступа | Есть токен, но нет прав на действие | DELETE /orders/{other_user_id} |
| **404 Not Found** | Ошибка клиента | Ресурс не существует | GET /products/999 (товар с таким ID не найден) |
| **500 Internal Server Error** | Ошибка сервера | Сбой на стороне сервера | POST /orders (внутренняя ошибка базы данных) |

## Что важно запомнить аналитику

1. **200 OK ≠ 201 Created:**
   - 200: данные уже существовали или операция не создавала ресурс
   - 201: сервер создал новый уникальный ресурс и вернул Location

2. **401 vs 403:**
   - 401: нет авторизации (нужно войти/получить токен)
   - 403: есть авторизация, но нет прав на это действие

3. **Клиент должен реагировать по-разному:**
   - На 401: перелогиниться или получить новый токен
   - На 403: показать сообщение «Нет прав доступа» (не нужно логиниться снова)

4. **204 No Content** — успешная операция без ответа в body (удаление, обновление).

## Типичные вопросы и ответы

**Q: В чём разница между 200 OK и 201 Created?**  
A: 200 OK используется для получения/обновления/удаления данных. 201 Created используется при создании нового ресурса, когда сервер возвращает Location созданного ресурса.

**Q: Когда использовать 401 вместо 403?**  
A: 401 — если нет токена или токен невалиден (нужно перелогиниться). 403 — если токен валидный, но у пользователя нет прав на это действие.

**Q: Что произойдёт, если сервер вернёт 200 вместо 201 при создании ресурса?**  
A: Клиент не получит Location созданного ресурса и не сможет перейти к нему. Это нарушение RESTful принципов.

# 3.25 JSON Schema — описание структуры данных в API

---

## 📌 Короткий ответ

> **JSON Schema** — это формат для описания структуры, типов и правил JSON-данных. Используется для валидации запросов/ответов API, генерации документации (OpenAPI), автокомплита в IDE.

---

## 💡 Простыми словами

### Аналогия с формой заказа

| Подход | Как работает |
|--------|--------------|
| **Без JSON Schema** | Клиент отправляет любые данные: `{name: 123, age: "twenty"}` — сервер проверяет только если захочет. |
| **С JSON Schema** | Есть чёткое описание формы: имя должно быть строкой, возраст числом от 0 до 150. Сервер сразу отклоняет некорректные данные. |

### Что описывает JSON Schema

- Какие поля есть в объекте
- Тип данных каждого поля (строка, число, булево)
- Обязательность полей
- Диапазоны значений
- Форматы (email, date, url)

---

## 🔍 Подробно

### Базовый пример JSON Schema

```json
{
  "type": "object",
  "properties": {
    "userId": {
      "type": "string",
      "pattern": "^U[0-9]+$"  // должен начинаться с U и цифрами
    },
    "userName": {
      "type": "string",
      "minLength": 2,
      "maxLength": 50
    },
    "age": {
      "type": "integer",
      "minimum": 18,
      "maximum": 120
    },
    "isActive": {
      "type": "boolean"
    }
  },
  "required": ["userId", "userName"]  // обязательные поля
}
```

**Что это описывает:**
- `userId` — строка, начинающаяся с буквы U и цифрами (например, `U123`)
- `userName` — строка от 2 до 50 символов
- `age` — число от 18 до 120
- `isActive` — булево значение
- `userId` и `userName` обязательны

---

### Типы данных в JSON Schema

| Тип | Пример | Когда использовать |
|-----|--------|-------------------|
| `"string"` | `"hello"`, `"user@example.com"` | Текстовые данные, email, url |
| `"number"` | `42.5`, `-10` | Дробные числа (целые — тоже number) |
| `"integer"` | `42`, `-7` | Только целые числа |
| `"boolean"` | `true`, `false` | Да/нет, включено/выключено |
| `"array"` | `[1, 2, 3]` | Списки значений |
| `"object"` | `{"name": "Ivan"}` | Объекты с полями |

### Дополнительные правила в JSON Schema

#### Для строк (`string`)
- `minLength`, `maxLength` — мин/макс длина
- `pattern` — регулярное выражение (например, email)
- `format` — стандартные форматы: `email`, `date`, `uri`, `uuid`

**Пример:**
```json
{
  "type": "string",
  "format": "email"  // валидирует как email
}
```

#### Для чисел (`number`, `integer`)
- `minimum`, `maximum` — мин/макс значение
- `multipleOf` — должно делиться на это число (например, цена с копейками)

**Пример:**
```json
{
  "type": "number",
  "minimum": 0,
  "maximum": 1000000,
  "multipleOf": 0.01  // цена только с копейками
}
```

#### Для массивов (`array`)
- `items` — схема элементов внутри массива
- `minItems`, `maxItems` — мин/макс количество элементов
- `uniqueItems` — элементы должны быть уникальными

**Пример:**
```json
{
  "type": "array",
  "items": {
    "type": "string"
  },
  "minItems": 1,
  "maxItems": 5
}
// разрешает: ["a"], ["a", "b", "c"]
// запрещает: [], ["a", "a"] (дубли не разрешены)
```

### JSON Schema в OpenAPI (Swagger)

OpenAPI использует JSON Schema для описания запросов и ответов.

**Пример из интернет-магазина:**
```yaml
# В OpenAPI спецификации:
paths:
  /api/v1/products:
    get:
      responses:
        '200':
          description: Список товаров
          content:
            application/json:
              schema:
                type: array
                items:
                  $ref: '#/components/schemas/Product'

components:
  schemas:
    Product:
      type: object
      required: [id, name, price]
      properties:
        id:
          type: integer
          description: Идентификатор товара
        name:
          type: string
          minLength: 1
          maxLength: 200
        price:
          type: number
          minimum: 0
```

**Что это даёт:**
- Автоматическая генерация документации
- Валидация запросов на стороне клиента
- Автокомплит в IDE (Postman, VS Code)

## ⚖️ Плюсы/минусы

### JSON Schema

| Плюсы ✅ | Минусы ❌ |
|----------|----------|
| Чёткое описание контракта | Может быть сложным для новичков |
| Автоматическая валидация | Не все инструменты поддерживают |
| Генерация документации | Требует поддержки и актуализации |
| Автокомплит в IDE | Переопределение схем может усложнить документацию |

## 🎯 Что важно запомнить аналитику

1. **JSON Schema — это контракт** между клиентом и сервером о структуре данных
2. **Используется в OpenAPI/Swagger** для описания API
3. **Позволяет автоматизировать**: генерацию документации, валидацию, автокомплит
4. **Можно ссылаться на схемы** (`$ref`) чтобы не дублировать определения
5. **Важно поддерживать актуальность** — если меняете API, обновляйте JSON Schema

## ❓ Типичные вопросы и ответы

### Q: Что такое JSON Schema?
**A:** Формат для описания структуры, типов и правил JSON-данных. Используется для валидации и документации API.

### Q: В чём разница между `number` и `integer` в JSON Schema?
**A:** `number` — любые числа (42.5, -10), `integer` — только целые (42, -7).

### Q: Как сделать поле обязательным в JSON Schema?
**A:** Добавить его в массив `required`: `"required": ["field_name"]`.

### Q: Что делает `$ref` в JSON Schema?
**A:** Ссылается на уже определённую схему, чтобы не дублировать определения.

### Q: Как валидировать email в JSON Schema?
**A:** Использовать `format: "email"` — это стандартный формат для проверки email.

## 🛠 Практические вопросы для собеседования

1. Объясните, что такое JSON Schema простыми словами.
2. Приведите пример JSON Schema для объекта заказа в интернет-магазине.
3. В чём разница между `number` и `integer`?
4. Как сделать поле обязательным в схеме?
5. Как JSON Schema используется в OpenAPI/Swagger?

**Ответы на практические вопросы:**

1. **JSON Schema — это как паспорт данных**: описывает, какие поля есть, какого они типа и какие правила должны соблюдаться. Например, для заказа: `orderId` — строка из цифр, `totalPrice` — число больше 0.

2. **Пример для заказа в интернет-магазине:**
   ```json
   {
     "type": "object",
     "required": ["orderId", "customerId", "items"],
     "properties": {
       "orderId": {"type": "string", "pattern": "^ORD-[0-9]+$"},
       "customerId": {"type": "integer", "minimum": 1},
       "totalPrice": {"type": "number", "minimum": 0, "multipleOf": 0.01},
       "items": {
         "type": "array",
         "minItems": 1,
         "items": {
           "type": "object",
           "properties": {
             "productId": {"type": "integer"},
             "quantity": {"type": "integer", "minimum": 1}
           }
         }
       },
       "status": {"type": "string", "enum": ["pending", "confirmed", "shipped"]}
     }
   }
   ```

3. **`number` — любые числа** (42, 42.5, -10), а **`integer` — только целые** (42, -7). В JSON нет отдельного типа для целых чисел, поэтому `integer` в JSON Schema — это подтип `number`.

4. **Добавить поле в массив `required`**:
   ```json
   "properties": {
     "name": {"type": "string"}
   },
   "required": ["name"]  // теперь name обязателен
   ```

5. **JSON Schema используется в OpenAPI/Swagger** для описания структуры запросов и ответов. Это позволяет:
   - Автоматически генерировать документацию
   - Валидировать запросы на стороне клиента (например, в Postman)
   - Получать автокомплит в IDE при написании кода

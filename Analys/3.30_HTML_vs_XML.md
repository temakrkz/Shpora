# 3.30 HTML vs XML: в чём разница и когда что использовать

📌 **Короткий ответ**  
HTML (HyperText Markup Language) — это язык разметки для веб-страниц, предназначенный для отображения в браузере. XML (eXtensible Markup Language) — это формат обмена данными между системами, который описывает структуру информации. HTML показывает данные людям, XML передаёт данные машинам.

> **HTML = для людей (браузеры), XML = для машин (системы).**

---

💡 **Простыми словами**  
Представьте ресторан:

**HTML — это меню для гостей:**
- Красивое оформление с картинками
- Понятные описания блюд
- Цены и рекомендации по подаче
- Гость читает и делает выбор

**XML — это заказ на кухню (внутренняя форма):**
- Строгая структура: "Блюдо №123, порция 200г, без орехов"
- Без лишних украшений
- Кухня (сервер) понимает только этот формат
- Гость не видит эту форму

В мире IT:
- **HTML** показывает данные пользователю в браузере
- **XML** передаёт структурированные данные между системами

🔍 **Подробно**  

## Что такое HTML?  

### Определение  
HTML (HyperText Markup Language) — это язык гипертекстовой разметки, используемый для создания веб-страниц. Он описывает структуру контента: заголовки, абзацы, изображения, ссылки и т.д.

### Как работает HTML?
1. **Браузер** получает HTML-код от сервера
2. Браузер интерпретирует теги (`<h1>`, `<p>`, `<img>` и т.д.)
3. Браузер отображает страницу с форматированием, стилями и изображениями

### Пример HTML:
```html
<!DOCTYPE html>
<html>
<head>
  <title>Интернет-магазин</title>
</head>
<body>
  <h1>Каталог товаров</h1>
  <p>Смартфон iPhone 15 — 9990 руб.</p>
  <img src="iphone.jpg" alt="iPhone 15">
  <a href="/buy/123">Купить</a>
</body>
</html>
```

### Для чего используется HTML?
- Отображение веб-страниц в браузере
- Создание интерактивных интерфейсов (кнопки, формы)
- Вставка изображений, видео, ссылок
- Поддержка стилей через CSS и скриптов через JavaScript

---

## Что такое XML?  

### Определение  
XML (eXtensible Markup Language) — это язык разметки для хранения и передачи структурированных данных между системами. Он позволяет создавать собственные теги для описания информации.

### Как работает XML?
1. **Система А** создаёт XML-файл с данными в определённой структуре
2. Передаёт файл через HTTP, email или файловый обмен
3. **Система Б** читает XML и извлекает данные по тегам

### Пример XML:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<catalog>
  <product id="123">
    <name>iPhone 15</name>
    <price currency="RUB">9990</price>
    <description>Смартфон Apple последнего поколения</description>
  </product>
</catalog>
```

### Для чего используется XML?
- Обмен данными между системами (API, файлы)
- Формат данных в SOAP-сообщениях
- Конфигурационные файлы приложений
- Валидация структуры данных через XSD (XML Schema Definition)

---

## Ключевые различия  

| Характеристика | HTML | XML |
|----------------|------|-----|
| **Цель** | Отображение в браузере | Передача данных между системами |
| **Аудитория** | Люди (через браузер) | Машины (системы, программы) |
| **Теги** | Фиксированный набор (`<h1>`, `<p>`) | Любые пользовательские теги |
| **Вложенность** | Ограничена семантикой | Полная вложенность разрешена |
| **Стилизация** | CSS (внешний вид) | Нет стилей (только данные) |
| **Интерпретация** | Браузер отображает красиво | Система парсит и извлекает данные |
| **Размер** | Может быть большим (с стилями) | Компактный, только структура данных |

## Примеры использования в интернет-магазине  

### HTML — для отображения страниц  
```html
<!-- Страница товара -->
<div class="product-card">
  <h2>iPhone 15</h2>
  <img src="/images/iphone.jpg" alt="iPhone 15">
  <p class="price">9990 руб.</p>
  <button onclick="addToCart(123)">В корзину</button>
</div>
```

**Когда используется:**
- Главная страница магазина
- Страница товара с описанием и фото
- Корзина и оформление заказа (визуальная часть)
- Личный кабинет пользователя

---

### XML — для обмена данными между системами  
```xml
<!-- Запрос к API -->
<orderRequest>
  <orderId>123</orderId>
  <customerId>456</customerId>
  <items>
    <item productId="iphone-15" quantity="1"/>
  </items>
</orderRequest>

<!-- Ответ от API -->
<orderResponse status="success">
  <orderId>123</orderId>
  <totalAmount currency="RUB">9990</totalAmount>
  <estimatedDelivery>2024-01-20</estimatedDelivery>
</orderResponse>
```

**Когда используется:**
- SOAP API для интеграции с другими системами
- Формат данных в отчётах и экспорт/импорт
- Конфигурационные файлы серверов
- Обмен данными через файловый обмен (FTP, SFTP)

## Плюсы/минусы  

### HTML ✅/❌

| Плюсы | Минусы |
|-------|--------|
| Понятен людям и браузерам | Не предназначен для передачи данных между системами |
| Поддержка стилей (CSS) и интерактивности (JS) | Медленный парсинг больших файлов |
| Широкая поддержка всех браузеров | Сложно валидировать структуру данных |
| Можно быстро создавать красивые страницы | Переизбыток данных для машинного чтения |

### XML ✅/❌

| Плюсы | Минусы |
|-------|--------|
| Строгая структура, легко валидировать (XSD) | Не предназначен для отображения в браузере |
| Универсальный формат обмена данными | Большой размер из-за избыточных тегов |
| Поддержка Unicode и кодировок | Медленный парсинг по сравнению с JSON |
| Широкая поддержка в enterprise-системах | Сложнее читать для людей |

---

## 🎯 Что важно запомнить аналитику  

1. **HTML не используется для передачи данных между системами** — только для отображения страниц людям.
2. **XML предназначен для машиночитаемых форматов**, когда важна строгая структура и валидация.
3. **В современных API чаще используют JSON вместо XML**, так как он компактнее и проще парсится.
4. **HTML может содержать данные внутри тегов** (например, `<div data-product-id="123">`), но это не формат обмена данными — это атрибуты для браузеров.

## ❓ Типичные вопросы и ответы  

### Q: Можно ли использовать XML вместо HTML на веб-странице?
**A:** Технически можно, но это плохая идея. Браузеры оптимизированы для HTML, а не XML. Если вы хотите передать данные системе — используйте XML (или JSON). Если нужно показать страницу человеку — используйте HTML.

### Q: Почему в современных API используют JSON вместо XML?
**A:** JSON проще парсится, занимает меньше места и ближе к JavaScript (языку браузеров). XML слишком громоздкий для передачи данных между веб-сервисами.

### Q: В чём разница между `<div>` в HTML и `<product>` в XML?
**A:** `<div>` — это контейнер для отображения контента в браузере, у него есть семантическое значение. `<product>` — пользовательский тег XML, который описывает данные товара для машинного чтения.

### Q: Можно ли валидировать HTML через XSD?
**A:** Нет, HTML не имеет строгой схемы. Для валидации HTML используют DTD (Document Type Definition) или HTML5 schema. XML валидируется через XSD (XML Schema Definition).

## 🛠 Практические вопросы для собеседования  

### 1. Когда использовать XML вместо JSON?
**Ответ:** XML лучше подходит, когда:
- Нужна строгая валидация структуры данных (через XSD)
- Интеграция с legacy-системами (старые ERP, CRM)
- Обмен через SOAP API
- Поддержка Unicode и кодировок критична

### 2. Почему HTML не подходит для передачи данных между системами?
**Ответ:** HTML содержит много лишней информации для машинного чтения: стили, скрипты, атрибуты для браузеров. XML (и JSON) — это чистые данные без "упаковки" под отображение в браузере.

### 3. Как проверить корректность XML-файла?
**Ответ:** Использовать XSD (XML Schema Definition) для валидации структуры данных или DTD (Document Type Definition). Также можно использовать онлайн-валидаторы или инструменты вроде xmlstarlet, xmllint.

### 4. В чём разница между HTML и XHTML?
**Ответ:** XHTML — это XML версия HTML с более строгими правилами: все теги должны быть закрыты, атрибуты в кавычках, элементы вложенны правильно. XHTML предназначен для использования как XML документа.

### 5. Можно ли отображать XML в браузере?
**Ответ:** Да, браузеры могут отображать XML (например, через `<pre>` или специальные виджеты), но это не то же самое, что HTML-страница. XML показывает сырой код с тегами, а HTML — интерпретированный контент.

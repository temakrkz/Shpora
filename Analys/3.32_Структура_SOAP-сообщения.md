# 3.32 Структура SOAP-сообщения: как устроены запросы и ответы

📌 **Короткий ответ**  
SOAP (Simple Object Access Protocol) — это протокол обмена сообщениями на основе XML. Каждое SOAP-сообщение имеет строгую структуру: заголовок с метаданными, тело с данными запроса/ответа и завершающая часть для ошибок.

> **SOAP = XML-обёртка вокруг данных + правила передачи между системами.**

---

Представьте отправку письма по почте:

**Обычное письмо:**
- Вы пишете текст на листе бумаги
- Кладёте в конверт
- Отправляете почтой

**SOAP-сообщение — это как официальное деловое письмо с оверлейми:**
1. **Конверт (Envelope)** — внешняя упаковка, указывает адресата и получателя
2. **Шапка (Header)** — служебная информация: кто отправил, тип сообщения, авторизация
3. **Письмо (Body)** — само сообщение с данными запроса или ответа
4. **Отметка об ошибке (Fault)** — если что-то пошло не так

В мире IT:
- **SOAP** — это формат обмена структурированными данными между системами через HTTP/SMTP/TCP
- **XML** используется для кодирования данных внутри SOAP-сообщения
- Строгая структура позволяет автоматизировать обработку сообщений

## Что такое SOAP?  

### Определение  
SOAP (Simple Object Access Protocol) — протокол обмена структурированными сообщениями, использующий XML для кодирования данных. Он работает поверх любых транспортных протоколов (чаще всего HTTP).

### Зачем нужен SOAP?
1. **Стандартизация** — все системы понимают формат сообщений одинаково
2. **Типобезопасность** — данные имеют чёткие типы и структуру
3. **Валидация** — можно проверить корректность сообщения через XSD
4. **Безопасность** — встроенная поддержка шифрования, цифровых подписей

### Когда используется SOAP?
- Enterprise-системы (банки, страховые компании)
- Интеграция с legacy-системами
- Сценарии, требующие строгой валидации и безопасности
- Протоколы, где важна надёжность доставки сообщений

## Структура SOAP-сообщения  

### 1. Envelope (Обёртка)  
Внешняя структура всего сообщения. Указывает, что это SOAP-сообщение.

```xml
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <!-- остальные части -->
</soap:Envelope>
```

**Что внутри:**
- Header (опционально) — служебная информация
- Body (обязательно) — данные запроса или ответа
- Fault (опционально) — ошибка, если что-то пошло не так

---

### 2. Header (Шапка)  
Служебная информация о сообщении: авторизация, маршрутизация, транзакции и т.д.

```xml
<soap:Header>
  <!-- Авторизация -->
  <ns1:AuthenticationToken xmlns:ns1="http://example.com/auth">
    <username>ivanov</username>
    <password>secret123</password>
  </ns1:AuthenticationToken>
  
  <!-- Транзакция -->
  <ns2:TransactionID xmlns:ns2="http://example.com/transaction">
    <id>TXN-123456</id>
  </ns2:TransactionID>
  
  <!-- Маршрутизация -->
  <ns3:ToAddress xmlns:ns3="http://example.com/routing">
    <address>https://api.example.com/orders</address>
  </ns3:ToAddress>
</soap:Header>
```

**Типичные данные в Header:**
- **Авторизация** — токен, пароль для доступа к API
- **Транзакция** — ID транзакции для отслеживания и отката операций
- **Маршрутизация** — адрес назначения сообщения
- **Обработка ошибок** — правила обработки ошибок (retry, timeout)

---

### 3. Body (Тело)  
Самые данные запроса или ответа. Содержит метод вызова и параметры.

```xml
<soap:Body>
  <!-- Запрос -->
  <ns1:GetOrderStatus xmlns:ns1="http://example.com/orders">
    <orderId>123</orderId>
  </ns1:GetOrderStatus>
  
  <!-- Ответ -->
  <ns1:GetOrderStatusResponse xmlns:ns1="http://example.com/orders">
    <orderStatus>shipped</orderStatus>
    <trackingNumber>TRK-789012</trackingNumber>
  </ns1:GetOrderStatusResponse>
</soap:Body>
```

**Что внутри:**
- **Запрос (Request)** — метод вызова и параметры
- **Ответ (Response)** — результат выполнения запроса

---

### 4. Fault (Ошибка)  
Служебная информация об ошибках, если что-то пошло не так.

```xml
<soap:Body>
  <soap:Fault>
    <faultcode>Error</faultcode>              <!-- Код ошибки -->
    <faultstring>Не удалось обработать заказ</faultstring>  <!-- Описание -->
    
    <!-- Детали ошибки (опционально) -->
    <detail>
      <errorInfo code="ORDER_NOT_FOUND">
        Заказ с ID=123 не найден
      </errorInfo>
    </detail>
  </soap:Fault>
</soap:Body>
```

**Структура Fault:**
- **faultcode** — код ошибки (например, `Client`, `Server`, `VersionMismatch`)
- **faultstring** — текстовое описание ошибки
- **detail** — дополнительные детали об ошибке (опционально)

## Полный пример SOAP-запроса и ответа  

### Запрос: Получить статус заказа  
```xml
POST /orders HTTP/1.1
Host: api.example.com
Content-Type: text/xml; charset=utf-8
SOAPAction: "http://example.com/orders/GetOrderStatus"

<soap:Envelope xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" 
               xmlns:xsd="http://www.w3.org/2001/XMLSchema"
               xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Header>
    <!-- Авторизация -->
    <ns1:AuthenticationToken xmlns:ns1="http://example.com/auth">
      <username>ivanov</username>
      <password>secret123</password>
    </ns1:AuthenticationToken>
    
    <!-- Транзакция -->
    <ns2:TransactionID xmlns:ns2="http://example.com/transaction">
      <id>TXN-789012</id>
    </ns2:TransactionID>
  </soap:Header>
  
  <soap:Body>
    <!-- Запрос метода -->
    <ns1:GetOrderStatus xmlns:ns1="http://example.com/orders">
      <orderId>123</orderId>
    </ns1:GetOrderStatus>
  </soap:Body>
</soap:Envelope>
```

---

### Ответ: Успешный результат  
```xml
HTTP/1.1 200 OK
Content-Type: text/xml; charset=utf-8

<soap:Envelope xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" 
               xmlns:xsd="http://www.w3.org/2001/XMLSchema"
               xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Header>
    <!-- Транзакция завершена -->
    <ns2:TransactionStatus xmlns:ns2="http://example.com/transaction">
      <status>completed</status>
    </ns2:TransactionStatus>
  </soap:Header>
  
  <soap:Body>
    <!-- Ответ метода -->
    <ns1:GetOrderStatusResponse xmlns:ns1="http://example.com/orders">
      <orderStatus>shipped</orderStatus>
      <trackingNumber>TRK-789012</trackingNumber>
      <estimatedDelivery>2024-01-20</estimatedDelivery>
    </ns1:GetOrderStatusResponse>
  </soap:Body>
</soap:Envelope>
```

---

### Ответ: Ошибка  
```xml
HTTP/1.1 500 Internal Server Error
Content-Type: text/xml; charset=utf-8

<soap:Envelope xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" 
               xmlns:xsd="http://www.w3.org/2001/XMLSchema"
               xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Body>
    <soap:Fault>
      <faultcode>Server</faultcode>              <!-- Серверная ошибка -->
      <faultstring>Не удалось обработать заказ</faultstring>
      
      <!-- Детали ошибки -->
      <detail>
        <errorInfo code="ORDER_NOT_FOUND">
          Заказ с ID=123 не найден в системе
        </errorInfo>
        
        <!-- Техническая информация (не для клиента) -->
        <technicalDetails>
          <exceptionType>OrderNotFoundException</exceptionType>
          <stackTrace>at OrderService.getOrder(OrderService.java:45)</stackTrace>
        </technicalDetails>
      </detail>
    </soap:Fault>
  </soap:Body>
</soap:Envelope>
```

## Примеры использования в интернет-магазине  

### Сценарий 1: Создание заказа через SOAP API  

**Запрос:**
```xml
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/">
  <soap:Body>
    <ns1:CreateOrder xmlns:ns1="http://example.com/orders">
      <customerId>456</customerId>
      <items>
        <item>
          <productId>789</productId>
          <quantity>2</quantity>

```

**Ответ:**
```xml

    <ns1:CreateOrderResponse xmlns:ns1="http://example.com/orders">
      <orderId>123</orderId>
      <status>created</status>
    </ns1:CreateOrderResponse>
  </soap:Body>
</soap:Envelope>
```

## Плюсы/минусы  

| Плюсы ✅ | Минусы ❌ |
|----------|----------|
| Строгая структура и валидация через XSD | Громоздкие сообщения (XML избыточен) |
| Типобезопасность — данные имеют чёткие типы | Медленный парсинг по сравнению с JSON |
| Встроенная поддержка безопасности (шифрование, подписи) | Сложность реализации и отладки |
| Широкая поддержка в enterprise-системах | Не подходит для веб-приложений (сложно читать) |
| Надёжность доставки сообщений | Устаревший подход по сравнению с REST/JSON |

---

## 🎯 Что важно запомнить аналитику  

1. **SOAP использует XML** — это его основной формат данных, что делает сообщения громоздкими.
2. **Строгая структура** позволяет автоматизировать обработку сообщений и валидацию через XSD.
3. **Встроенная поддержка безопасности** (цифровые подписи, шифрование) важна для финансовых систем.
4. **SOAP устарел для веб-приложений**, но остаётся актуальным для enterprise-интеграций.

## ❓ Типичные вопросы и ответы  

### Q: В чём разница между SOAP и REST?
**A:** SOAP — это строгий протокол с XML-сообщениями, встроенной валидацией и безопасностью. REST — архитектурный стиль, который чаще использует JSON и HTTP-методы. SOAP больше подходит для enterprise-систем, REST — для веб-приложений.

### Q: Почему SOAP медленнее REST?
**A:** XML громоздкий (много служебных тегов), требует больше времени на парсинг. JSON компактнее и проще обрабатывается в браузерах.

### Q: Можно ли использовать SOAP поверх HTTP?
**A:** Да, чаще всего SOAP работает через HTTP с Content-Type: text/xml. Также может работать через SMTP, TCP и другие транспортные протоколы.

### Q: Что такое WS-Security в контексте SOAP?
**A:** Это стандарт безопасности для SOAP-сообщений, позволяющий добавлять цифровые подписи, шифрование и авторизацию внутри SOAP Header.

## 🛠 Практические вопросы для собеседования  

### 1. Когда использовать SOAP вместо REST?
**Ответ:** SOAP лучше подходит, когда:
- Требуется строгая валидация через XSD
- Интеграция с legacy-системами (банки, страховые)
- Важна встроенная безопасность (WS-Security)
- Нужна надёжность доставки сообщений

### 2. Как обработать ошибку SOAP Fault?
**Ответ:** Парсить элемент `<soap:Fault>` внутри Body и читать поля faultcode, faultstring, detail для получения информации об ошибке. Также проверять HTTP-статус ответа (500, 400 и т.д.).

### 3. Можно ли использовать SOAP в мобильных приложениях?
**A:** Технически можно, но это плохая идея из-за громоздкости XML. Лучше использовать REST/JSON для мобильных приложений.

### 4. Что такое WSDL и как он связан с SOAP?
**Ответ:** WSDL (Web Services Description Language) — это XML-файл, описывающий SOAP-сервис: какие методы доступны, какие параметры принимают, где находится сервис. WSDL используется для генерации клиентского кода на разных языках.

### 5. Как проверить корректность SOAP-сообщения?
**Ответ:** Использовать валидатор XML с XSD схемой, проверять соответствие структуры (Envelope → Header/Body → Fault), убедиться в наличии обязательных элементов.

# 3.33 WSDL: описание SOAP-сервисов для клиентов

📌 **Короткий ответ**  
WSDL (Web Services Description Language) — это XML-файл, описывающий SOAP-сервис: какие методы доступны, какие параметры принимают и возвращают, где находится сервис. Это "паспорт" сервиса для разработчиков.

> **WSDL = документация SOAP-сервиса в машиночитаемом формате.**

---

💡 **Простыми словами**  
Представьте ресторан:

**Меню — это WSDL:**
- Список всех доступных блюд (методов)
- Описание ингредиентов и способов приготовления (параметров)
- Цены и время приготовления (типы данных, ограничения)
- Как сделать заказ (протокол связи)

**Повар на кухне — это SOAP-сервис:**
- Принимает заказы по меню
- Готовит блюда
- Возвращает результат

**Гость — это клиент:**
- Читает меню (WSDL), чтобы понять, что можно заказать
- Делает заказ через меню
- Получает блюдо

В мире IT:
- **WSDL** описывает SOAP-сервис в XML-формате
- Разработчик читает WSDL и генерирует клиентский код
- Клиент использует сгенерированный код для вызова методов сервиса

🔍 **Подробно**  

## Что такое WSDL?  

### Определение  
WSDL (Web Services Description Language) — это XML-формат для описания веб-сервисов. Он содержит информацию:
- Какие методы доступны в сервисе
- Какие параметры они принимают и возвращают
- Где находится сервис (URL endpoint)
- Какой протокол используется (SOAP, HTTP и т.д.)

### Зачем нужен WSDL?
1. **Документация** — описание сервиса для разработчиков
2. **Автогенерация кода** — из WSDL можно сгенерировать клиентский код на разных языках
3. **Стандартизация** — единый формат описания сервисов

### Когда используется WSDL?
- SOAP-сервисы (REST не использует WSDL)
- Интеграция enterprise-систем
- Генерация клиентского кода для вызова методов сервиса

---

## Структура WSDL  

WSDL-файл состоит из нескольких секций:

### 1. Types (Типы данных)  
Описание используемых типов данных (XML Schema).

```xml
<types>
  <xs:schema targetNamespace="http://example.com/orders" 
             xmlns:xs="http://www.w3.org/2001/XMLSchema">
    
    <!-- Тип заказа -->
    <xs:complexType name="OrderType">
      <xs:sequence>
        <xs:element name="orderId" type="xs:int"/>
        <xs:element name="status" type="xs:string"/>
      </xs:sequence>
    </xs:complexType>
    
  </xs:schema>
</types>
```

---

### 2. Message (Сообщения)  
Описание структуры сообщений (запросов и ответов).

```xml
<messages>
  
  <!-- Сообщение запроса: получить статус заказа -->
  <message name="GetOrderStatusRequest">
    <part name="orderId" type="xs:int"/>
  </message>
  
  <!-- Сообщение ответа: статус заказа -->
  <message name="GetOrderStatusResponse">
    <part name="order" type="tns:OrderType"/>
  </message>
  
</messages>
```

**Что внутри:**
- **Request message** — структура запроса к методу
- **Response message** — структура ответа от метода
- **Part** — часть сообщения (поле/параметр)

---

### 3. PortType (Операции)  
Описание методов сервиса (операций).

```xml
<portType name="OrderPortType">
  
  <!-- Операция: получить статус заказа -->
  <operation name="GetOrderStatus">
    <message name="GetOrderStatusRequest" 
             part="orderId"/>
    <message name="GetOrderStatusResponse" 
             part="order"/>
  </operation>
  
  <!-- Операция: создать заказ -->
  <operation name="CreateOrder">
    <message name="CreateOrderRequest" 
             part="order"/>
    <message name="CreateOrderResponse" 
             part="orderId"/>
  </operation>
  
</portType>
```

**Что внутри:**
- **Operation** — метод сервиса (например, `GetOrderStatus`)
- **Input/Output** — какие сообщения принимает и возвращает операция

---

### 4. Binding (Связывание)  
Описание того, как операции реализованы через конкретный протокол (SOAP).

```xml
<binding name="OrderSoapBinding" 
         type="tns:OrderPortType">
  
  <!-- Связывание с SOAP -->
  <soap:binding style="document" 
                transport="http://schemas.xmlsoap.org/soap/http"/>
  
  <!-- Операция GetOrderStatus -->
  <operation name="GetOrderStatus">
    <soap:operation soapAction="http://example.com/orders/GetOrderStatus"/>
    
    <!-- Входные данные -->
    <input message="tns:GetOrderStatusRequest">
      <soap:header 
        part="AuthToken" 
        message="tns:AuthenticationToken"/>
      <body>
        <part name="orderId" type="xs:int"/>
      </body>
    </input>
    
    <!-- Выходные данные -->
    <output message="tns:GetOrderStatusResponse">
      <body>
        <part name="order" type="tns:OrderType"/>
      </body>
    </output>
  </operation>
  
</binding>
```

**Что внутри:**
- **Protocol binding** — как работает операция (SOAP, HTTP)
- **Input/Output** — где передаются данные (header, body)
- **SoapAction** — действие операции для маршрутизации

---

### 5. Service (Сервисы)  
Описание доступных сервисов и их адресов.

```xml
<services>
  
  <!-- Сервис заказов -->
  <service name="OrderService">
    <port name="OrderSoapPort" 
          binding="tns:OrderSoapBinding">
      <soap:address location="https://api.example.com/orders"/>
    </port>
  </service>
  
</services>
```

**Что внутри:**
- **Service** — логическая группа портов (сервис)
- **Port** — конкретный endpoint сервиса с URL
- **Location** — адрес, куда отправлять SOAP-запросы

## Полный пример WSDL  

### Пример: SOAP-сервис интернет-магазина  
```xml
<?xml version="1.0" encoding="UTF-8"?>
<wsdl:definitions xmlns:wsdl="http://schemas.xmlsoap.org/wsdl/"
                  xmlns:soap="http://schemas.xmlsoap.org/wsdl/soap/"
                  xmlns:xs="http://www.w3.org/2001/XMLSchema"
                  xmlns:tns="http://example.com/orders"
                  targetNamespace="http://example.com/orders">
  
  <!-- Типы данных -->
  <wsdl:types>
    <xs:schema targetNamespace="http://example.com/orders" 
               xmlns:xs="http://www.w3.org/2001/XMLSchema">
      
      <xs:complexType name="OrderType">
        <xs:sequence>
          <xs:element name="orderId" type="xs:int"/>
          <xs:element name="status" type="xs:string"/>
          <xs:element name="totalAmount" type="xs:decimal"/>
        </xs:sequence>
      </xs:complexType>
      
    </xs:schema>
  </wsdl:types>
  
  <!-- Сообщения -->
  <wsdl:message name="GetOrderStatusRequest">
    <wsdl:part name="orderId" type="xs:int"/>
  </wsdl:message>
  
  <wsdl:message name="GetOrderStatusResponse">
    <wsdl:part name="order" type="tns:OrderType"/>
  </wsdl:message>
  
  <!-- Операции -->
  <wsdl:portType name="OrderPortType">
    <wsdl:operation name="GetOrderStatus">
      <wsdl:input message="tns:GetOrderStatusRequest" 
                  name="request"/>
      <wsdl:output message="tns:GetOrderStatusResponse" 
                   name="response"/>
    </wsdl:operation>
  </wsdl:portType>
  
  <!-- Связывание -->
  <wsdl:binding name="OrderSoapBinding" 
                type="tns:OrderPortType">
    <soap:binding style="document" 
                  transport="http://schemas.xmlsoap.org/soap/http"/>
    
    <wsdl:operation name="GetOrderStatus">
      <soap:operation soapAction="http://example.com/orders/GetOrderStatus"/>
      
      <wsdl:input name="request">
        <soap:header 
          part="AuthToken" 
          message="tns:AuthenticationToken"/>
        <body>
          <part name="orderId" type="xs:int"/>
        </body>
      </wsdl:input>
      
      <wsdl:output name="response">
        <body>
          <part name="order" type="tns:OrderType"/>
        </body>
      </wsdl:output>
    </wsdl:operation>
  </wsdl:binding>
  
  <!-- Сервис -->
  <wsdl:service name="OrderService">
    <wsdl:port name="OrderSoapPort" 
               binding="tns:OrderSoapBinding">
      <soap:address location="https://api.example.com/orders"/>
    </wsdl:port>
  </wsdl:service>
  
</wsdl:definitions>
```

## Примеры использования в интернет-магазине  

### Сценарий: Интеграция с ERP-системой  

**Ситуация:** Интернет-магазин хочет интегрироваться с ERP-системой для синхронизации остатков товаров.

**Шаг 1: Получение WSDL от ERP-системы**
```xml
<!-- ERP присылает WSDL -->
<wsdl:definitions>
  <wsdl:service name="InventoryService">
    <wsdl:port binding="tns:InventoryBinding">
      <soap:address location="https://erp.example.com/inventory"/>
    </wsdl:port>
  </wsdl:service>
</wsdl:definitions>
```

**Шаг 2: Магазин читает WSDL и понимает:**
- Сервис доступен по адресу `https://erp.example.com/inventory`
- Есть метод `GetStock(productId)` для получения остатков
- Метод принимает `productId` (число) и возвращает `stockQuantity` (число)

**Шаг 3: Генерация клиентского кода**
```java
// Сгенерированный код из WSDL
public class InventoryService {
    public int getStock(int productId) throws SOAPException {
        // Код для вызова метода через SOAP
    }
}
```

**Шаг 4: Использование в приложении магазина**
```java
InventoryService service = new InventoryService();
int stock = service.getStock(123);  // Получаем остаток товара
```

## Плюсы/минусы  

| Плюсы ✅ | Минусы ❌ |
|----------|----------|
| Автогенерация клиентского кода на разных языках | Устаревший формат (XML, громоздкий) |
| Единый стандарт описания SOAP-сервисов | Не подходит для REST/GraphQL |
| Подробная документация для разработчиков | Сложность чтения и понимания |
| Типобезопасность — данные имеют чёткие типы | Требует настройки сервера для публикации WSDL |

---

## 🎯 Что важно запомнить аналитику  

1. **WSDL используется только для SOAP-сервисов**, REST не использует этот формат.
2. **Из WSDL можно сгенерировать клиентский код** на разных языках (Java, C#, Python и т.д.).
3. **WSDL — это документация**, а не реализация сервиса. Он описывает, что сервис делает, но не содержит кода самого сервиса.
4. **Современные API чаще используют OpenAPI/Swagger вместо WSDL**, так как REST/JSON проще для веб-приложений.

## ❓ Типичные вопросы и ответы  

### Q: В чём разница между WSDL и OpenAPI?
**A:** WSDL описывает SOAP-сервисы (XML, строгий протокол). OpenAPI (ранее Swagger) описывает REST API (JSON, HTTP-методы). WSDL больше подходит для enterprise-систем, OpenAPI — для веб-приложений.

### Q: Можно ли использовать WSDL для REST API?
**A:** Нет, WSDL предназначен только для SOAP. Для REST используется OpenAPI/Swagger.

### Q: Где в WSDL указан адрес сервиса?
**A:** В секции `<service>` → `<port>` → `<soap:address location="..."/>`. Это URL endpoint, куда отправлять запросы.

### Q: Как сгенерировать клиентский код из WSDL?
**A:** Использовать инструменты вроде `wsimport` (Java), `svcutil` (.NET) или онлайн-конвертеры. Они читают WSDL и генерируют классы для вызова методов сервиса.

## 🛠 Практические вопросы для собеседования  

### 1. Что будет, если клиент не сможет прочитать WSDL?
**Ответ:** Клиент не сможет сгенерировать код для взаимодействия с сервисом. Разработчик должен вручную изучить документацию или использовать инструменты отладки (Postman) для тестирования запросов.

### 2. Как обновить WSDL при изменении сервиса?
**Ответ:** Обновить XML-файл WSDL на сервере, где он публикуется. Клиенты должны скачать новую версию и сгенерировать код заново. Важно уведомлять клиентов об изменениях для обратной совместимости.

### 3. Можно ли использовать WSDL без SOAP?
**Ответ:** Технически можно создать WSDL-файл для любого сервиса, но это не имеет смысла — WSDL предназначен именно для SOAP. Для REST используйте OpenAPI/Swagger.

### 4. Как проверить корректность WSDL файла?
**Ответ:** Использовать валидатор XML с XSD схемой для WSDL или онлайн-валидаторы (например, w3.org services/validator). Также можно попытаться сгенерировать код из WSDL — если есть ошибки, генерация не завершится.

### 5. Где обычно размещается WSDL файл?
**Ответ:** Обычно по URL вида `https://api.example.com/services/OrderService.wsdl` или в секции `<soap:address>` самого сервиса с параметром `?wsdl`.

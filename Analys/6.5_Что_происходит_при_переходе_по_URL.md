# 6.5 Что происходит при переходе по URL 📌

> **Короткий ответ**  
> При вводе URL браузер: находит IP-адрес сервера через DNS, устанавливает защищённое соединение (HTTPS), отправляет запрос и получает ответ с данными сайта.

---

## 💡 Простыми словами

Представьте что вы хотите отправить письмо другу по адресу `friend@example.com`:

**Что происходит:**
1. Вы пишете письмо → это как формируем HTTP-запрос
2. Ищете адрес друга в справочнике (DNS) → переводим домен в IP
3. Отправляем письмо почтой → устанавливаем соединение с сервером
4. Письмо доходит до получателя → сервер отвечает данными сайта

---

## 🔍 Подробно

### Этапы перехода по URL

```
1. Пользователь вводит: https://shop.example.com/products
    ↓
2. Браузер проверяет кэш DNS (быстро!)
   Если нет — обращается к DNS-серверу
    ↓
3. DNS переводит домен в IP-адрес
   shop.example.com → 192.168.1.100
    ↓
4. Браузер устанавливает соединение с сервером (TCP handshake)
    ↓
5. Если HTTPS — происходит SSL/TLS рукопожатие (шифрование)
    ↓
6. Браузер отправляет HTTP-запрос:
   GET /products HTTP/1.1
   Host: shop.example.com
    ↓
7. Сервер обрабатывает запрос и возвращает ответ
    ↓
8. Браузер получает HTML, CSS, JS, картинки
    ↓
9. Браузер собирает всё в страницу и показывает пользователю
```

## 🛠 Пример из интернет-магазина

### Сценарий: переход на страницу товаров

**URL:** `https://shop.example.com/products?category=electronics`

#### Шаг 1: DNS разрешение
```
Браузер спрашивает DNS сервер:
"Какой IP у shop.example.com?"

DNS отвечает:
"IP-адрес: 192.168.1.100"
```

**Что это:** Как телефонистка узнаёт номер телефона по имени.

#### Шаг 2: Установление соединения (TCP)
```
Браузер → "Привет, хочу подключиться к 192.168.1.100"
Сервер   → "Принято, я готов!"
Браузер → "Подтверждаю соединение"
Сервер   → "Соединение установлено!"
```

**Что это:** Как звонок по телефону — ждём пока друг поднимет трубку.

#### Шаг 3: SSL/TLS рукопожатие (для HTTPS)
```
Браузер: "Покажи свой сертификат"
Сервер:  [отправляет цифровой паспорт сервера]
Браузер: "Проверяю... Сертификат валиден!"
Оба:    "Договариваемся о ключах шифрования"
```

**Что это:** Как проверка личности курьера — чтобы убедиться что он действительно из почты.

#### Шаг 4: HTTP-запрос
```
Браузер отправляет:
GET /products?category=electronics HTTP/1.1
Host: shop.example.com
User-Agent: Mozilla/5.0
Accept: application/json
```

**Что это:** Как вы говорите "покажи мне каталог электроники".

#### Шаг 5: Ответ сервера
```
Сервер отвечает:
HTTP/2 200 OK

[Данные в формате JSON или HTML]
{
  "products": [
    {"id": 1, "name": "Ноутбук", "price": 50000},
    {"id": 2, "name": "Телефон", "price": 30000}
  ]
}
```

**Что это:** Как курьер приносит вам каталог товаров.

#### Шаг 6: Браузер собирает страницу
```
Браузер получает:
- HTML (структура страницы)
- CSS (стили и оформление)
- JavaScript (интерактивность)
- Картинки товаров

Собирает всё вместе → показывает пользователю!
```

**Что это:** Как вы складываете все части каталога на стол.

## ⚖️ Плюсы/минусы

| ✅ Преимущества процесса | ❌ Недостатки |
|-------------------------|--------------|
| Автоматическое разрешение доменов | Задержка DNS (10-200мс) |
| Защищённое соединение (HTTPS) | Дополнительное время на шифрование |
| Кэширование DNS ускорение | Зависимость от DNS серверов |

---

## 🎯 Что важно запомнить аналитику

1. **DNS — критичный этап** — если он не работает, сайт не откроется
2. **HTTPS добавляет задержку ~50-200мс** из-за рукопожатия
3. **Браузер кэширует DNS** — второй раз переход будет быстрее
4. **Всё происходит автоматически** — пользователь видит только результат

## ❓ Типичные вопросы и ответы

**В: Что такое DNS и зачем он нужен?**  
О: DNS (Domain Name System) — это телефонная книга интернета. Он переводит понятные людям домены (`shop.example.com`) в IP-адреса серверов (`192.168.1.100`), по которым компьютеры находят друг друга.

**В: Почему сайт может долго грузиться при первом входе?**  
О: Потому что браузер должен разрешить DNS (спросить у DNS-сервера IP адрес), установить TCP-соединение и провести SSL/TLS рукопожатие для шифрования. Это добавляет задержки.

**В: Что будет если сервер не отвечает на запрос?**  
О: Браузер будет ждать до таймаута (обычно 30 секунд) а потом покажет ошибку "Не удалось подключиться" или "Сайт недоступен".

---

## 🛠 Практические вопросы для собеседования

**В: Почему переход по URL во второй раз быстрее первого?**  
→ Ответ: Потому что браузер кэширует DNS-запись и уже установленное соединение. Не нужно снова спрашивать IP у DNS сервера и проводить SSL/TLS рукопожатие.

**В: Что такое "зелёный замок" в браузере при HTTPS?**  
→ Ответ: Это индикация что соединение защищено — браузер успешно провёл SSL/TLS рукопожатие, сертификат проверен и данные будут передаваться зашифрованными.

**В: Почему иногда сайт показывает ошибку "Не удалось разрешить домен"?**  
→ Ответ: Потому что DNS сервер не смог найти IP-адрес для указанного домена. Это может быть из-за проблем с DNS, неправильного написания URL или недоступности самого сайта.

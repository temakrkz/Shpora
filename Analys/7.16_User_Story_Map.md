# 7.16. User Story Map

> 📌 **Короткий ответ**  
> User Story Map — это визуальная карта всех пользовательских сценариев продукта, от самых важных до мелких деталей. Она показывает полную картину функционала и помогает приоритизировать работу.

---

## 💡 Простыми словами

Представьте карту путешествия:
- **Верхний уровень**: основные этапы пути (отель → достопримечательности → рестораны)
- **Детали**: что делать на каждом этапе (заселиться, посмотреть музей, пообедать)
- **Приоритеты**: сначала отель и дорога, потом музеи

**В примере с интернет-магазином:**
```
Верхний уровень: Покупка товара
  ├─ Найти товар
  ├─ Добавить в корзину
  ├─ Оформить заказ
  └─ Получить товар

Детали "Найти товар":
  ├─ Поиск по названию
  ├─ Фильтры (цена, бренд)
  ├─ Сортировка
  └─ Просмотр фото
```

---

## 🔍 Подробно

### Что это такое

**User Story Map** — визуализация всех пользовательских историй (user stories), сгруппированных по эпикам и функциям. Это горизонтальная карта, где:
- **Ось X**: процесс/путь пользователя (от начала до конца)
- **Ось Y**: детализация (эпики → функции → детали)

### Зачем нужна

1. **Полная картина**: видно всё функционал целиком, а не по кусочкам
2. **Приоритизация**: сверху — самое важное, снизу — мелкие улучшения
3. **Коммуникация**: вся команда видит общую цель
4. **Roadmap**: легко превратить в план релизов

### Как строится

**Шаг 1: Карточка (Card)**  
Определяете основные действия пользователя:
```
Купить товар → Оформить заказ → Получить товар
```

**Шаг 2: Эпики (Epics)**  
Группируете по крупным функциям:
```
Поиск и выбор товара
Корзина и оформление
Доставка и оплата
Личный кабинет
```

**Шаг 3: User Stories**  
Разбиваете эпики на истории:
```
Как покупатель, я хочу фильтровать товары, чтобы быстро найти нужный
Как покупатель, я хочу видеть фото товара, чтобы проверить качество
```

**Шаг 4: Детали**  
Добавляете мелкие фичи под каждую историю:
```
Фильтры → по цене, бренду, рейтингу, наличию
Фото → галерея, зум, видео-обзор
```

### Пример из интернет-магазина

**Путь покупателя:**
```
1. Регистрация/Вход
   ├─ Зарегистрироваться через email
   ├─ Войти по паролю
   └─ Войти через соцсети

2. Поиск товара
   ├─ Поиск по названию
   ├─ Фильтры (цена, бренд, размер)
   ├─ Сортировка (популярное, новинки)
   └─ Просмотр категории

3. Карточка товара
   ├─ Фото и описание
   ├─ Характеристики
   ├─ Отзывы
   └─ Выбор опций (цвет, размер)

4. Корзина
   ├─ Добавить товар
   ├─ Изменить количество
   └─ Удалить товар

5. Оформление заказа
   ├─ Ввод данных доставки
   ├─ Выбор способа оплаты
   ├─ Подтверждение заказа
   └─ Оплата

6. Получение товара
   ├─ Отслеживание статуса
   ├─ Получение курьером
   └─ Оставление отзыва
```

**Приоритизация:**
- **MVP (первый релиз)**: Регистрация, Поиск 1 уровень, Карточка товара базовая, Корзина, Оформление заказа без оплаты
- **Релиз 2**: Фильтры, Фото/описание, Отзывы, Выбор опций
- **Релиз 3**: Соцсети, Изменение количества в корзине, Отслеживание статуса

## ⚖️ Плюсы и минусы

| Плюсы | Минусы |
|-------|--------|
| ✅ Видна полная картина продукта | ❌ Может стать слишком большой для больших продуктов |
| ✅ Легко приоритизировать (сверху вниз) | ❌ Требует времени на создание |
| ✅ Помогает команде понять контекст | ❌ Быстро устаревает при изменениях |
| ✅ Упрощает планирование релизов | ❌ Не показывает технические детали |

---

## 🎯 Что важно запомнить аналитику

1. **User Story Map — это не список задач**  
   Это карта путей пользователя, из которой потом выводят задачи

2. **Всегда сверху вниз**  
   Сначала основные сценарии (MVP), потом детали и улучшения

3. **Фокус на пользователе**  
   Каждая история начинается с "Как пользователь..."

4. **Это живая документация**  
   Обновляйте при каждом изменении требований

5. **Помогает говорить с командой**  
   Разработчики видят, что делать, тестировщики — что проверять

## ❓ Типичные вопросы и ответы

### Что такое User Story Map?
Это визуальная карта всех пользовательских историй продукта, организованная по путям пользователя. Показывает полную картину функционала от MVP до мелких деталей.

### Зачем нужна User Story Map?
- Видна полная картина продукта
- Легко приоритизировать (сверху — главное)
- Команда понимает контекст
- Упрощается планирование релизов

### Чем отличается от обычного списка задач?
Список задач — это вертикальный список "что сделать". User Story Map показывает горизонтальные пути пользователя и связи между функциями. Это карта, а не чеклист.

### Как строить User Story Map?
1. Определите основные пути пользователя (покупка, регистрация)
2. Разбейте на эпики (крупные функции)
3. Добавьте user stories под каждый эпик
4. Детализируйте до мелких фич
5. Приоритизируйте сверху вниз

### Когда обновлять User Story Map?
При каждом значимом изменении требований, после каждого спринта или релиза, при нахождении новых инсайтов от пользователей.

## 🛠 Практические вопросы для собеседования

**Вопрос 1:** Что такое User Story Map и зачем она нужна?  
→ Ответ: Визуальная карта всех пользовательских историй продукта, организованная по путям пользователя. Помогает видеть полную картину, приоритизировать и планировать релизы.

**Вопрос 2:** Как строится User Story Map?  
→ Ответ: 1) Определяют основные пути пользователя; 2) Разбивают на эпики; 3) Добавляют user stories под каждый эпик; 4) Детализируют до мелких фич; 5) Приоритизируют сверху вниз.

**Вопрос 3:** Чем User Story Map отличается от обычного списка задач?  
→ Ответ: Список задач — вертикальный чеклист "что сделать". User Story Map показывает горизонтальные пути пользователя и связи между функциями, это карта, а не просто список.

**Вопрос 4:** Когда обновлять User Story Map?  
→ Ответ: При каждом значимом изменении требований, после спринтов/релизов, при нахождении новых инсайтов от пользователей.

**Вопрос 5:** Как использовать User Story Map для планирования релизов?  
→ Ответ: Берут верхние слои (MVP) для первого релиза, следующие уровни — для последующих. Это помогает дробить большой функционал на управляемые части.

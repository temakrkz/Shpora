# 7.21. 5W1H и CJM

> 📌 **Короткий ответ**  
> **5W1H** — метод анализа требований через 6 вопросов: Who, What, Where, When, Why, How. **CJM (Customer Journey Map)** — карта пути клиента от первого контакта до покупки и далее. Оба инструмента помогают понять процесс целиком.

---

## 💡 Простыми словами

### 5W1H — как задавать правильные вопросы

Представьте, что вы хотите заказать пиццу:
- **Who** (Кто) — для кого заказываем?
- **What** (Что) — какую пиццу хотим?
- **Where** (Где) — куда доставляем?
- **When** (Когда) — когда нужен заказ?
- **Why** (Почему) — зачем именно эта пицца?
- **How** (Как) — как будем получать?

Так и с требованиями: задаём 6 вопросов, чтобы понять всё.

---

### CJM — карта пути клиента

Представьте карту путешествия туриста:
- Откуда приехал → куда едет → что делает на каждом этапе → какие эмоции испытывает

CJM показывает путь пользователя через систему от первого шага до финала (и далее).

---

## 🔍 Подробно

### 5W1H — метод анализа требований

**Что это:**  
Метод структурированного сбора информации через 6 вопросов:
- **Who** — кто участвует/использует?
- **What** — что происходит/требуется?
- **Where** — где происходит?
- **When** — когда происходит?
- **Why** — зачем это нужно (цель)?
- **How** — как это происходит/реализуется?

---

#### 1. Who (Кто)

**Что спрашиваем:**
- Кто пользователь? (роль, должность)
- Кто заказчик?
- Кто принимает решение?
- Кто влияет на процесс?

**Пример из интернет-магазина:**
```
Who:
- Пользователь: покупатель товара
- Заказчик: отдел маркетинга
- Принимающий решение: менеджер по продажам
- Влияющие: бухгалтерия (проверка оплаты)
```

---

#### 2. What (Что)

**Что спрашиваем:**
- Что нужно сделать?
- Какие функции требуются?
- Какие данные нужны?
- Какой результат ожидается?

**Пример из интернет-магазина:**
```
What:
- Пользователь хочет добавить товар в корзину
- Система должна сохранять выбранные опции (цвет, размер)
- Нужно показать итоговую сумму заказа
- Результат: заказ создан и ожидает оплаты
```

---

#### 3. Where (Где)

**Что спрашиваем:**
- Где происходит действие? (страница, устройство, система)
- Где хранятся данные?
- Где интегрируется с другими системами?

**Пример из интернет-магазина:**
```
Where:
- Действие происходит на странице "Корзина"
- Данные хранятся в БД пользователя и корзине
- Интеграция с платежным шлюзом для оплаты
```

---

#### 4. When (Когда)

**Что спрашиваем:**
- Когда действие должно произойти? (время, условие)
- Как часто повторяется?
- Какие временные ограничения?

**Пример из интернет-магазина:**
```
When:
- Корзина сохраняется автоматически при добавлении товара
- Заказ должен быть создан в течение 15 минут после оформления
- Оплата должна пройти за 24 часа, иначе заказ отменяется
```

---

#### 5. Why (Почему)

**Что спрашиваем:**
- Зачем это нужно? (бизнес-цель)
- Какую проблему решает?
- Какую ценность приносит пользователю?

**Пример из интернет-магазина:**
```
Why:
- Корзина нужна, чтобы пользователь не терял выбранные товары
- Сохранение опций позволяет быстро вернуться к покупке
- Автоматическое создание заказа ускоряет процесс покупки
```

---

#### 6. How (Как)

**Что спрашиваем:**
- Как происходит действие? (шаги процесса)
- Как реализуется технически?
- Какие инструменты используются?

**Пример из интернет-магазина:**
```
How:
- Пользователь нажимает "Добавить в корзину" → товар сохраняется в БД
- Система показывает уведомление "Товар добавлен"
- При переходе к оформлению данные подтягиваются из корзины
- Оплата через API платежного шлюза
```

---

### CJM (Customer Journey Map) — карта пути клиента

**Что это:**  
Визуальная карта всех точек контакта пользователя с продуктом/сервисом от первого знакомства до покупки и далее.

**Зачем нужна:**
- Понять полный путь пользователя, а не отдельные шаги
- Выявить "боли" (проблемные точки) на каждом этапе
- Увидеть эмоции пользователя в процессе
- Найти возможности для улучшений

---

#### Структура CJM

CJM обычно состоит из 4 горизонтальных линий:

**1. Этапы пути (Stages)**  
От первого контакта до финала и далее:
```
Узнал о магазине → Перешёл на сайт → Нашёл товар → Добавил в корзину 
→ Оформил заказ → Получил товар → Оставил отзыв
```

**2. Действия пользователя (Actions)**  
Что пользователь делает на каждом этапе:
```
Смотрит рекламу → Заходит на сайт → Ищет товары → Фильтрует по цене 
→ Выбирает товар → Добавляет в корзину → Вводит данные оплаты 
→ Ждёт подтверждения → Получает заказ → Пишет отзыв
```

**3. Мысли и эмоции (Thoughts & Feelings)**  
Что пользователь думает и чувствует:
```
"Интересно, что у них есть?" → "Много товаров, не могу найти нужный" 
→ "Хорошо, нашёл подходящий" → "Надеюсь, доставка быстрая" 
→ "Уже оплатил, жду подтверждения" → "Получил, всё хорошо!" 
→ "Хочу оставить отзыв"
```

**4. Точки контакта (Touchpoints)**  
Где и как пользователь взаимодействует с продуктом:
```
Рекламная кампания в соцсетях → Сайт (мобильное приложение) 
→ Страница товара → Корзина → Платежный шлюз → Email-уведомления 
→ Курьерская служба → Форма отзыва
```

---

## 🛠 Пример CJM из интернет-магазина

### Сценарий: Покупка первого товара

**Этап 1: Узнаёт о магазине**
- **Действие:** Видит рекламу в Instagram
- **Мысли/эмоции:** "Интересно, что у них есть? Цены адекватные?"
- **Точка контакта:** Instagram реклама
- **Проблемы:** Нет кнопки "Перейти на сайт" (нужна оптимизация)

**Этап 2: Переходит на сайт**
- **Действие:** Кликает по ссылке, открывается сайт
- **Мысли/эмоции:** "Сайт грузится долго..."
- **Точка контакта:** Браузер + сайт магазина
- **Проблемы:** Медленная загрузка (нужно кэширование)

**Этап 3: Ищет нужный товар**
- **Действие:** Вводит запрос в поиск, фильтрует по цене
- **Мысли/эмоции:** "Хорошо работает поиск", "Много вариантов"
- **Точка контакт:** Страница поиска + фильтры
- **Проблемы:** Нет фильтра по бренду (нужно добавить)

**Этап 4: Выбирает товар и добавляет в корзину**
- **Действие:** Читает описание, смотрит фото, нажимает "Купить"
- **Мысли/эмоции:** "Хороший товар, надеюсь доставка быстрая"
- **Точка контакта:** Карточка товара + корзина
- **Проблемы:** Нет видео-обзора товара (нужно добавить)

**Этап 5: Оформляет заказ**
- **Действие:** Вводит данные доставки, выбирает оплату
- **Мысли/эмоции:** "Надеюсь, не попросят лишних данных"
- **Точка контакта:** Страница оформления заказа + платежный шлюз
- **Проблемы:** Много полей для заполнения (нужно автозаполнение)

**Этап 6: Ждёт подтверждения и доставки**
- **Действие:** Следит за статусом заказа
- **Мысли/эмоции:** "Где мой заказ?", "Когда будет курьер?"
- **Точка контакта:** Email-уведомления + трекер заказа
- **Проблемы:** Нет push-уведомлений (нужно добавить)

**Этап 7: Получает товар и оставляет отзыв**
- **Действие:** Получает заказ, проверяет качество, пишет отзыв
- **Мысли/эмоции:** "Всё хорошо, буду покупать ещё" / "Товар не соответствует описанию"
- **Точка контакта:** Курьер + форма отзыва
- **Проблемы:** Форма отзыва сложная (нужно упростить)

## ⚖️ Плюсы и минусы методов

### 5W1H

| Плюсы | Минусы |
|-------|--------|
| ✅ Простой и быстрый метод сбора информации | ❌ Может упустить детали, если вопросы задавать формально |
| ✅ Помогает структурировать мысли | ❌ Не показывает полную картину процесса (только отдельные аспекты) |
| ✅ Подходит для интервью со стейкхолдерами | ❌ Требует опыта, чтобы правильно сформулировать вопросы |

### CJM

| Плюсы | Минусы |
|-------|--------|
| ✅ Видна полная картина пути пользователя | ❌ Требует времени на создание и анализ |
| ✅ Выявляет "боли" на каждом этапе | ❌ Может быть слишком детальной для больших продуктов |
| ✅ Помогает понять эмоции пользователя | ❌ Нужно обновлять при изменениях процесса |

---

## 🎯 Что важно запомнить аналитику

1. **5W1H — это вопросы, CJM — это карта**  
   5W1H помогает собрать информацию, CJM визуализирует процесс целиком

2. **Используйте оба метода вместе**  
   Сначала задавайте 5W1H-вопросы для сбора информации, потом строьте CJM на основе ответов

3. **CJM — это про эмоции**  
   Важно не только "что делает пользователь", но и "как он себя чувствует"

4. **Оба метода помогают найти проблемы**  
   AS-IS через 5W1H/CJM → TO-BE как решение проблем

5. **Обновляйте CJM при изменениях**  
   Если процесс изменился — обновите карту, чтобы не терять контекст

## ❓ Типичные вопросы и ответы

### Что такое метод 5W1H?
Метод анализа требований через 6 вопросов: Who (кто), What (что), Where (где), When (когда), Why (почему), How (как). Помогает структурировать информацию о процессе или требовании.

### Зачем нужны вопросы "Why" и "How"?
"Why" помогает понять бизнес-цель и ценность требования, "How" — как это реализуется технически. Без этих вопросов можно упустить суть задачи.

### Что такое CJM?
CJM (Customer Journey Map) — карта пути клиента от первого контакта с продуктом до покупки и далее. Показывает этапы, действия пользователя, мысли/эмоции и точки контакта с системой.

### Как строить CJM?
1. Определите целевую аудиторию и сценарий использования
2. Разбейте путь на этапы (от первого шага до финала)
3. Для каждого этапа опишите: действия, мысли/эмоции, точки контакта
4. Выявите проблемы ("боли") на каждом этапе
5. Предложите решения для проблем

### Чем 5W1H отличается от CJM?
5W1H — это метод сбора информации через вопросы (аналитический инструмент). CJM — визуальная карта процесса с акцентом на эмоции пользователя (инструмент коммуникации и выявления проблем).
